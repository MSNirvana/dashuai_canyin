## 二、硬阻断：代码没提交，部署会拉错版本

这是本次核对里**最危险的一条**，且不在原部署文档的清单里。

**事实**：

```
当前分支 main，local main == origin/main（落后 0 个提交）
工作区未提交改动：100 个
```

未提交的内容里包含部署方案的**前提本身**：

| 未提交项 | 后果 |
|---|---|
| `server/src/lib/config.ts`（`PAYMENTS_ENABLED` 支付开关） | 拉到旧代码后**没有这个开关**，`NODE_ENV=production` 会强制校验微信支付七项 → **启动直接失败** |
| `deploy/`（README / deploy.sh / nginx / ecosystem / env 模板） | 服务器上根本没有部署脚本 |
| `server/prisma/migrations/20260914{1800,1900,2000,2100}*`（4 个新迁移） | 缺 `grant_register_balance` / `absorbed_beans` 等列，**代码与表结构不匹配** |
| `server/scripts/*`（本日新增 9 个验证脚本） | 无法在服务器上复跑回归 |
| `apps/mini/src/app.config.ts`、`apps/admin/*` 等前端改动 | 出包内容与本地不一致 |

> 注意 `deploy/deploy.sh` **不做 `git pull`**，它假设 `/opt/dashuai` 里的代码已经是最新。
> 所以「先把代码推上去」不是可选项，而是前置动作。

**处理**：先把工作区提交并推送，再在服务器上 `git clone`（或对已有目录 `git pull`）。

## 三、需你提供的输入（3 项，缺一不可）

### 1. 域名

仓库里**没有任何真实域名**，`deploy/` 下全是 `REPLACE_DOMAIN` 占位符，共 6 处待替换：

| 文件 | 位置 |
|---|---|
| `deploy/env.server.template` | `CORS_ORIGIN`、`WX_PAY_NOTIFY_URL` |
| `deploy/nginx/dashuai-api.conf` | `server_name` ×2、证书路径 ×3 |
| `deploy/nginx/dashuai-admin.conf` | `server_name` ×2、证书路径 ×2 |

需要两个子域（**必须 HTTPS**）：

```
api.<你的域名>      → 小程序接口（request / uploadFile）
admin.<你的域名>    → 运营后台静态站 + /admin/api/v1
```

**请提供**：主域名是什么、在哪里注册的（决定 DNS 在哪家控制台改）。

### 2. DNS：A 记录

你上次说「DNS 解析还没做」——这仍是部署的必要条件，且**必须早于申请证书**：
certbot 校验域名归属时要能解析到服务器，A 记录没生效就会签证书失败。

```
api.<你的域名>    A   <服务器公网 IP>
admin.<你的域名>  A   <服务器公网 IP>
```

**请提供**：服务器公网 IP（A 记录指向它），以及是否已建好这两条记录。

### 3. 服务器 SSH 凭据

仓库里**没有任何服务器地址或 IP 记录**，我也无从推断。

**请提供**：公网 IP / 登录用户（root 还是普通用户）/ 认证方式（密钥文件路径 或 密码）/ 是否有 sudo。
另外确认服务器规格能否跑合成：**内存 ≥ 4G**（PM2 里 `max_memory_restart: 3G`），且是 Ubuntu 22.04 / Debian 12 一类。

## 六、部署时最容易踩的 6 个点

1. **微信后台域名白名单**（每月修改次数有限，一次配全）。
   `request` → `api.<域名>`；`uploadFile` → `api.<域名>` + `dashuai-1485028436.cos.ap-beijing.myqcloud.com`；
   `downloadFile` → `dashuai-1485028436.cos.ap-beijing.myqcloud.com`。
   > 上面的 COS 域名由 `server/.env` 的 `COS_BUCKET=dashuai-1485028436` + `COS_REGION=ap-beijing` 拼出。
   > 填的时候**只填域名，不带 `https://`、不带端口**。

2. **支付先显式关掉**：`PAYMENTS_ENABLED=false`。
   ⚠ 这一项**不设置等于开启**，生产忘配支付凭据会拒绝启动。

3. **`APP_MASTER_KEY` 必须重新生成且与本地不同**：`openssl rand -hex 32`（64 位十六进制）。
   改了它必须重新 `npm run db:seed`（AI 通道 Key 用它加密）。

4. **换掉默认数据库口令**：`docker-compose.yml` 里是 `CHANGE_ME`，生产校验也会拒绝含 `changeme` / `123456` 的弱口令字样。

5. **COS 碎片生命周期规则（今日新增建议）**：
   上传中途失败会留下「未完成的分片上传」，它们**不是对象**，对象列表和本项目的 GC 默认都看不到，但**照样占存储计费**。建议在 COS 控制台配一条「碎片过期自动删除」规则（例如 7 天），无需人工干预。
   服务端也提供了手动通道：`npx tsx scripts/gc-orphan-objects.ts --abort-fragments`。

6. **`ffmpeg` 要含 libass**：字幕烧录依赖 `subtitles` 滤镜，缺了会降级成「只有配音没有字幕」。
   自检：`ffmpeg -hide_banner -filters | grep subtitles`。

## 七、一切就绪后的执行顺序

```bash
# 0) 本地：提交并推送（当前硬阻断）
#    （在仓库根目录执行）

# 1) 服务器初始化（一次性）：Node20 / ffmpeg+libass / Docker / PM2 / nginx
#    详见 deploy/README.md 第 2 节

# 2) 拉代码
mkdir -p /opt/dashuai && cd /opt/dashuai
git clone https://github.com/MSNirvana/dashuai_canyin.git .

# 3) 生成 env 并替换所有 REPLACE_*
cp deploy/env.server.template server/.env
vi server/.env && chmod 600 server/.env

# 4) 一键部署（幂等，可反复跑）
bash deploy/deploy.sh

# 5) nginx 域名替换 + HTTPS
sed -i 's/api.REPLACE_DOMAIN/api.<域名>/g; s/admin.REPLACE_DOMAIN/admin.<域名>/g' /etc/nginx/conf.d/dashuai-*.conf
certbot --nginx -d api.<域名> -d admin.<域名>   # 前提：A 记录已生效

# 6) 外网验证
curl -sS https://api.<域名>/healthz

# 7) 本地出包并上传体验版
bash scripts/build-weapp-prod.sh https://api.<域名>/api/v1
#    然后用微信开发者工具打开 apps/mini → 上传 → 到 mp.weixin.qq.com 设为体验版
```
