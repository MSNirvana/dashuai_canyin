## 结论先行

走 **「上传体验版 + 每个人自己打开『开发调试』」**。

关键机制：**微信官方允许"手机开启调试模式时不校验服务器域名"** —— 所以未备案 + http + IP 地址这套组合，在体验版上**能跑通**。这是整条路的命门，也是它能成立的全部原因。

你要做的只有四件事：

1. **决定后端地址**（局域网 IP 还是公网 IP）—— 只差 `.env` 里一行
2. **出包**（`.env` 改完必须重新构建，地址是构建期烘焙进产物的）
3. **上传 → 后台选为体验版 → 加体验成员**
4. **把「右上角 `···` → 开发调试」这句话发给每个测试的人**（漏了这步，他们看到的是「网络请求失败」）

## 四、出包

> ★ **卡死的真因不是「`dist` 已存在」，而是宿主的批量删除闸**：`taro build` 开工前会
> `emptyDirectory(dist)` 递归清空产物，而宿主的 safe-delete 会统计**本轮累计删除数**，
> **≥50 就要求「批量删除确认」**；没人确认时它**不报错、就那么挂着**。
> 有**两种**解法，A 是正解：

```bash
cd /Users/gaoyunhong/Documents/ChatGPT/Evvvv/apps/mini

# 方式 A（首选）：让闸放行，正常「清空 + 重建」
#   ★ approve 与构建必须在同一条命令里 —— 授权绑的是**这一次工具调用**的 id，
#     单开一次调用去 approve 对下一次构建无效。
GUARD="/Applications/WorkBuddy.app/Contents/Resources/app.asar.unpacked/cli/vendor/shim/safe-delete-bulk-guard.cjs"
node "$GUARD" approve --scope turn && npm run build:weapp:dev

# 方式 B（兜底）：先把旧产物挪走，让 taro 没东西可删（代价：/tmp 攒一堆备份）

```

`build:weapp:dev` = `taro build --type weapp` + `node scripts/verify-weapp-dist.mjs`，后者会校验产物里的接口地址等契约，**看到它通过才算成功**（实测 32 秒）。

**真的卡住了怎么判**（别去改代码、也别怀疑工程配置）：

```bash
# ① 是「在等」还是「在算」：etime 与 time 差距悬殊 = 在等，不是慢
ps -o pid,etime,time,%cpu,command -p $(pgrep -f "taro build" | head -1)

# ② 直接读闸的状态：toolApprovals 为空 = 确认请求发出去了、没人批 ⇒ 就是本条
S=$(printf '%s' "$CODEBUDDY_SESSION_ID" | shasum -a 256 | awk '{print $1}')
cat "$CODEBUDDY_SAFE_DELETE_BULK_STATE_DIR/$S/state.json"
```

处置：`kill` 掉那条 `taro build` 进程链（连同上面几层 `npm run` / `sh -c`），再用方式 A 重跑。

⚠ **构建冻在「已清空、还没回写」的中间态时，微信开发者工具会报**：
`根据 project.config.json 中 miniprogramRoot 指定的 dist/weapp/，在该目录下未找到 app.json`。

## 七、六个坑（都踩得起，但要知道）

### 坑 1 · ★★★ 绝对不要在公网服务端开 `DEV_LOGIN`

可能会想「测试期让服务端开个开发登录，测试者就不必走微信授权了」。**不要。** 代码里有双重护栏，硬开只有一条路 —— 把那台公网服务器降级成 `NODE_ENV=development`，代价是**八个生产守卫同时失效**：

```
server/src/auth/auth.service.ts:132   if (NODE_ENV === 'production' || DEV_LOGIN !== 'true') throw new Error('dev login disabled')
server/src/lib/config.ts:45           if (DEV_LOGIN === 'true' || MOCK_AI === 'true') throw new Error('Demo features forbidden in production')
```

`server/src/lib/config.ts:6` 写着这八个守卫的名单：**`JWT_SECRET` / `APP_MASTER_KEY` / `CORS_ORIGIN` / `DEV_LOGIN` / `MOCK_AI` / `FFMPEG_WORKER` / `STORAGE_MODE` / `COS_*`**。
⇒ 一旦降级，JWT 密钥回落到默认值 —— **公网上任何人都能伪造任意商户的登录态**。这是拿整个后台换测试便利，不划算。

**用 `getPhoneNumber` 微信一键登录就行，已验证服务端凭据有效（见第一节）。**

### 坑 2 · `getPhoneNumber` 要求小程序已认证 `[未证实，需要你确认]`

登录页走的是 `openType='getPhoneNumber'`（`apps/mini/src/pages/mine/index.tsx:472`），服务端再去调微信的「手机号快速验证」接口换真实手机号。
**这个能力微信要求小程序完成认证**，个人主体小程序用不了。而且它是**按次计费**的（`server/src/auth/wechat.ts:4` 有注释）。

⇒ **出包上传前，务必先自己用体验版点一次登录按钮。** 这是整条链路的入口，入口不通，后面全无意义。
如果真的不可用，兜底是回到短信验证码登录 —— 但那条路现在线上没配（返 `1004`），且在局域网下才用得通固定测试码 `123456`。

### 坑 3 · http 明文会把 token 明文送出去

这次是 `http://`，登录 token、手机号都在公网明文传。
⇒ **只发给内部可信的人、只用测试账号、别让他们录入真实商户的真实经营数据。** 备案下来切 https 之后才谈得上正式。

### 坑 4 · 局域网 IP 有隐性时效

换 WiFi、路由器重启、电脑睡眠唤醒，`192.168.1.13` 可能就变了；而且你电脑/后端一关，所有人立刻打不开。
⇒ 局域网路线只适合**当面、限时**的测试。

### 坑 5 · 「未备案能不能上传体验版」我没有官方依据 `[未证实]`

开发版 / 体验版**不需要审核**这点是官方明确的；但「未完成小程序 ICP 备案时，上传入口会不会被拦」我在官方文档里**没找到明文**，第三方资料里两种说法都有（有的说会被拦、有的说上传不影响、只拦发布）。

⇒ **请先在开发者工具里点一次「上传」看结果** —— 它要么成功，要么给你一句明确的拦截原因，试一次比猜十次快。如果真被拦，退路是「预览二维码」（工具栏「预览」→ 生成二维码 → 开发者本人/项目成员扫码真机运行，同样可以在真机右上角打开调试），只是覆盖的人更少、更临时。

### 坑 6 · 服务端部署脚本不跑提示词同步

`deploy/deploy.sh` 的 7 步里第 6 步只有 `npm run db:seed`。
但本项目的**提示词唯一源是 `server/prisma/prompts.ts`**，要生效必须**单独跑 `npm run ai-prompts:sync`**（`db:seed` 不负责这件事，两个不能互相替代）。

⇒ 部署后**必须补跑一次**，否则 AI 生成用的还是库里的旧模板。

**另外本轮还欠两步**（生产 `/opt/dashuai`）：

- `npx prisma db push` —— 要加 `user_idea` 列（创作页「你想怎么拍？」）和 `TutorialVideo` 表（教学中心）
- nginx 的 `/admin/api/v1/` location 要加 `client_max_body_size 20m;` —— 否则后台上传教学视频/轮播图会被 nginx 用默认 1MB 挡掉

# 附二 · 2026-09-18 更新：**后台也可以走 IP 直开**，以及一个 100MB 上传的坑

## 1. ★★ 新增一条更省事的路：只测**运营后台**的话，完全不碰微信

`apps/admin/vite.config.ts` 没有设 `base`（默认 `/`）⇒ 产物 `index.html` 引用的是
**绝对路径** `/assets/index-*.js`；而 `apps/admin/src/lib/http.ts:21` 的
`baseURL: '/admin/api/v1'` 是**相对路径**。两条合在一起意味着：

> 后台静态站**和 API 同源**，所以只要 nginx 把静态站挂到**根路径**，
> `http://49.232.243.241/` 就能直接给外地的人用浏览器开 —— **不需要域名、不需要 https、不受备案影响、不碰微信**。

⚠ 两个反直觉点：

- **不能挂在 `/admin/` 下**：产物引用的是 `/assets/…`（绝对），挂在 `/admin/` 会被浏览器请求到
  `/assets/…`，匹配不到 `/admin/` 而落到兜底 location ⇒ **白屏**，且控制台只报 404。
  （改 `base: '/admin/'` 也能解决，但会连带影响本机 dev 的 `http://127.0.0.1:5173/`，不划算。）
- **挂根路径是安全的**：服务端所有路由都在 `/api/v1` 或 `/admin/api/v1` 下
  （`server/src/index.ts:57-93` 逐个核对过），根路径只有 `/healthz` ⇒ SPA 的
  `try_files … /index.html` 吃不到任何接口。nginx 按**最长前缀**选 location，
  所以 `/admin/api/v1/` 一定优先于 `/`。

## 2. ★ nginx `client_max_body_size` 曾是 20m —— 会把整条「精品交付」挡死

`deploy/nginx/dashuai-dev-ip.conf` 原来是 `20m`。而现在后端有**两条 100MB 级别的上传通道**：

| 通道 | 上限 | 常量位置 |
|---|---|---|
| 教学中心课程视频 | 100MB | `server/src/services/tutorial.service.ts::MAX_TUTORIAL_VIDEO_BYTES` |
| 精品交付成片（2026-09-18 新增） | 100MB | `server/src/services/premium-delivery.service.ts::MAX_DELIVER_VIDEO_BYTES` |

⇒ 20m 会把它们挡在门外，返回 **nginx 自己的英文 413 页面**（不是后端 JSON 信封），
而且**本地开发完全测不出来**（vite 直连 3000、不过 nginx）。

**已改为 `110m`**（= 100m + 表单开销），三处必须同值：服务端常量、前端选文件时的预校验、本行。

## 3. 本次对 `deploy/nginx/dashuai-dev-ip.conf` 的改动

从「全部反代给 API」改成「API + 后台静态站」：

```nginx
server {
    listen 80 default_server;  listen [::]:80 default_server;  server_name _;
    client_max_body_size 110m;                       # ← 20m 改这里
    root  /opt/dashuai/apps/admin/dist;  index index.html;   # ← 新增（server 级）
    location = /healthz  { proxy_pass http://127.0.0.1:3000/healthz; access_log off; }
    location /admin/api/v1/ { proxy_pass http://127.0.0.1:3000; … }   # 显式列出，钉住约束
    location /api/v1/       { proxy_pass http://127.0.0.1:3000; … }
    location / { try_files $uri $uri/ /index.html; }                   # ← SPA
    location ~* \.(js|css|…)$ { expires 7d; try_files $uri =404; }      # =404 必须带
}
```

三条容易踩的约束（已写进文件头注释）：

1. **本文件是全站唯一的 `default_server`**。再现加一个 `listen 80 default_server` 会让 nginx
   **直接起不来**：`a duplicate default server for 0.0.0.0:80`。所以别新建第二个 conf，
   要加东西就加在这个 server 块里。
2. **与 `dashuai-admin.conf`（443 + certbot 证书）别同时启用**。那个文件是给备案后的
   `admin.<域名>` 用的；当前无证书无域名，启用它会让 80 端口的隐式 default server 变成它、
   IP 直连一律 500（文件头里有这段历史）。备案后再 `sudo rm` 本文件。
3. 静态资源那条 regex location **必须带 `try_files $uri =404`**：否则一个不存在的 `.js`
   会返回 nginx 的 HTML 404 页，浏览器报 `Unexpected token '<'`，看不出是「前端产物没传上去」。

## 补 · 2026-09-18 实测：「开发调试」开了还报「域名未加入合法域名」怎么办

上传体验版当天就撞上了这条。先把**不变的判据**记下来：

- **产物侧确认无问题**：`apps/mini/dist/weapp` 全量扫过，出现的 http(s) 地址里
  **只有一处 IP** —— `http://49.232.243.241`（来自 `apps/mini/.env` 的 `TARO_APP_API_BASE_URL`，构建期烘焙），
  **没有任何 `dspcz.top` 残留**。所以「请求打到了没配置的域名」这个猜测**不成立**。
  真因是：微信真机（正式版/体验版）**只允许 HTTPS 域名**，且**不允许 IP、http、端口、路径** ——
  当前这个地址属于「三条都占」的形态，**必须靠跳过校验才能走**。
- **后台配置这条路当前是死的**（实测）：`https://dspcz.top` → `curl` 返回 `000`（443 没开、无证书）；
  `http://dspcz.top` → `302`（备案拦截页，备案未过）。
  ⇒ 既没有 HTTPS，域名也没备案，**微信后台根本加不进去**。所以唯一通路仍是「开发调试」。
- 图片同样受影响：素材/封面走腾讯云 COS 域名，也在域名校验范围内，
  所以**开调试之前往往「图也裂」**——可以拿它当辅助判据（登录通了但图还裂，就是另一个问题）。

### 开了开关却不生效的四种情况（按出现频率排序）

| # | 情况 | 判据 | 修法 |
|---|---|---|---|
| 1 | **开完没重启小程序** | 开关已开，重进仍报错 | 微信首页**下拉** → 长按该小程序 → 拖到底部**删除** → 重新扫码进入 |
| 2 | **手机上有旧版本缓存** | 之前装过开发版/预览版 | 同上「删除」时**把开发版/体验版/正式版全删**，再重新扫码 |
| 3 | **打开的不是开发版/体验版** | `···` 菜单里**根本没有「开发调试」这一项** | 多半是从**转发的卡片/分享**进入 → 一律**扫体验版二维码**重新进 |
| 4 | **身份不对** | 同一个小程序，别人能进你不行 | 确认微信号在「体验成员」名单里；微信社区有「管理员/开发者本人打开体验版反而被拦、体验成员正常」的案例 |

> ⚠ 还有个**永远不适用**的情况：**正式版**没有开发调试开关，任何配置都不可能生效 ——
> 所以别把体验版二维码发出去后被当成「正式版链接」到处转发。

### 等备案通过后的正解（顺序别乱）

1. nginx 加 443 + 证书（现在**只有 80**），`api.dspcz.top` **DNS 已解析**到同一台机器，只差这一段；
2. 小程序后台 →「开发管理 → 开发设置 → 服务器域名」：`https://api.dspcz.top` 加进 **request 合法域名**，
   COS 域名加进 **downloadFile 合法域名**（微信要求 HTTPS + 已备案，不能 IP/端口/路径）；
3. `apps/mini/.env` 的 `TARO_APP_API_BASE_URL` 改成 `https://api.dspcz.top/api/v1` → **重新出包上传**；
4. 通知测试者**关掉**「开发调试」（配好域名后开着反而会掩盖配置错误）。

> 备选（若备案拖很久且测试者多、不想教每个人开调试）：用**小程序云开发的云函数做转发**
> —— 云函数调用不受合法域名限制。代价是要改代码 + 开通云开发，**非必要不动**。
