# 详细设计 03 · AI 网关与系统配置中心

> 项目：大帅餐饮短视频创作工具　|　版本：v1.0
> 需求来源：甲方要求——主通道 DeepSeek V4、**必须有备用通道**、**兼容 GPT / Claude 等其他模型**、**后台可配置**、**后台可一键通道测试**

---

## 1. 设计目标

| 目标 | 做法 |
|---|---|
| 供应商无关 | 业务层只依赖 `ai_scene`，永不直接引用具体模型 |
| 型号不写死 | 模型型号、价格、上下文长度全部存表，后台维护 |
| 故障自动转移 | 主通道失败 → 按序切备用通道 → 全失败返回兜底模板（不扣豆） |
| 故障快速失败 | 滑动窗口熔断器，避免每次请求干等超时 |
| 可观测可测试 | 后台一键测试连通性/延迟/费用；调用日志留全量快照 |
| 成本可控 | 每通道可设月度预算上限，超限自动降级到下一通道 |

---

## 2. 分层架构

```
业务层（ai/copy、ai/storyboard、admin/shot-library）
        │  只传 sceneCode + 变量
        ▼
┌─────────────────── AI Gateway ───────────────────┐
│ 1. 读 ai_scene：模板 + 默认模型 + 备用链 + 标价    │
│ 2. Provider 选择（熔断状态 / 预算 / 优先级）        │
│ 3. 协议适配器（OPENAI_COMPATIBLE / ANTHROPIC_NATIVE）│
│ 4. 调用 → 失败重试 → 故障转移                      │
│ 5. 成本计算（价格表）→ ai_call_log                 │
│ 6. 全失败 → 返回兜底模板                          │
└───────────────────────────────────────────────────┘
        │
        ▼
DeepSeek V4（主） / GPT（备1） / Claude（备2） / 通义 / 豆包 / 自定义
```

**协议适配器**
- `OPENAI_COMPATIBLE`：DeepSeek、通义千问、豆包、混元、以及绝大多数国产模型——统一走 `/chat/completions`
- `ANTHROPIC_NATIVE`：Claude 原生 Messages API，单独写一个 adapter 转出统一结构

新增供应商只需：后台填 base_url + key + 选协议 + 填模型价格，**不改代码**。

## 3. 调用时序

```
1. 按 sceneCode 取 ai_scene（模板、defaultModelId、fallbackModelIds、timeoutMs、maxRetries）
2. 组装候选链：[defaultModel, ...fallbackModelIds]
3. 依次尝试（同一模型内可重试 maxRetries 次）：
   a. 检查 provider.enabled && health_status != DOWN && 未熔断 && 预算未超
   b. 渲染 prompt 模板 → 发起调用（超时 = scene.timeoutMs）
   c. 成功 → 计算 costFen → 写 ai_call_log（isFallback 标记）→ 返回
   d. 失败 → 记录失败，滑动窗口 +1；继续下一个候选
4. 全部失败 → 返回兜底模板（isFallbackTemplate=true），业务层不扣豆
```

**兜底模板要求**：每个 `ai_scene` 必须配一份静态兜底内容（文案模板 / 通用分镜结构），保证通道全挂时流程不断。

## 4. 熔断器

| 参数 | 配置键 | 默认 |
|---|---|---|
| 滑动窗口大小 | `ai.circuit_window_size` | 20 次 |
| 失败率阈值 | `ai.circuit_fail_threshold` | 0.5 |
| 熔断时长 | `ai.circuit_open_seconds` | 60 秒 |

- 窗口内失败率超阈值 → `health_status=DOWN`，`circuit_open_until = now + 60s`
- 熔断期间该通道直接跳过，不等超时（这是关键，否则用户每次等 30s）
- 到期转半开：放 1 个请求探测，成功则恢复 HEALTHY，失败再熔断

## 5. 通道测试（后台）

### 单通道测试 `POST /admin/ai/providers/:id/test`
```json
// req
{ "modelCode": "deepseek-v4" }
// res
{ "data": {
    "status": "SUCCESS",
    "latencyMs": 842,
    "modelReturned": "deepseek-v4",
    "promptTokens": 8, "completionTokens": 16,
    "estimatedCostFen": 1,
    "errorMsg": null
}}
```

**实现要点**
- 发极短探测请求：`{"messages":[{"role":"user","content":"ping"}]}`，`max_tokens=16`，超时 10s
- 写 `ai_call_log` 且 `status=TEST`、`merchant_id=NULL`，**不参与毛利统计**
- 回写 `ai_provider.last_test_at / last_test_latency_ms / last_test_status / last_test_error`
- 测试失败不影响熔断器状态（测试是主动行为，不算业务失败）

### 批量测试 `POST /admin/ai/providers/test-all`
并发测所有 `enabled=1` 的通道，返回列表，前端按状态着色（绿 / 黄 / 红）。

### 后台页面建议
- 通道列表：名称、类型、协议、优先级、健康状态、最近测试时间与延迟、本月已用预算
- 一键"测试全部"
- 拖拽或填数字调整优先级
- 启用/停用开关
- 密钥只显示脱敏，修改需二次确认

## 6. 模型价格与成本

- 价格单位：**分 / 百万 tokens**（`input_price_per_mtok`、`output_price_per_mtok`），整数存储，杜绝浮点误差
- 成本计算：
```
costFen = ceil(promptTokens × inputPrice  / 1_000_000)
        + ceil(completionTokens × outputPrice / 1_000_000)
```
- 每通道可设 `monthly_budget_fen`，`used_budget_fen` 累加，超限自动跳过该通道并告警
- **金价变动时只需后台改 `ai_model` 价格行**，无需发版

> ⚠ **DeepSeek V4 说明**：V4 的确切定价、上下文与输出上限以官方发布为准，上线时由管理员在后台"AI 模型"页填写即可，代码不写死任何型号。上线前建议先用通道测试跑一次，确认 base_url 与模型标识正确。

## 7. 密钥安全

| 措施 | 说明 |
|---|---|
| 加密存储 | `api_key_encrypted` 用 AES-256-GCM，主密钥放环境变量 `APP_MASTER_KEY`，**不进代码库** |
| 脱敏回显 | 接口只返回 `api_key_masked`（如 `sk-****1234`） |
| 日志脱敏 | `ai_call_log` 快照禁止落 key；错误消息统一清洗 |
| 修改审计 | 密钥变更记后台操作日志 |
| 传输 | 全站 HTTPS；Base URL 强制 https 校验 |

| **upload** | max_file_size_mb | 2048 | 单文件上限 |
| | recommend_size_mb | 500 | 建议大小 |
| **ai** | circuit_window_size | 20 | 熔断窗口 |
| | circuit_fail_threshold | 0.5 | 熔断失败率 |
| | circuit_open_seconds | 60 | 熔断时长 |
| | default_timeout_ms | 30000 | 默认超时 |
| **message** | wx_tmpl_render_done | — | 订阅消息模板 ID |
| | wx_tmpl_member_expire | — | |
| | wx_tmpl_bean_low | — | |
| | bean_low_threshold | 50 | 豆余额告警阈值 |

**实现要点**
- 配置读多写少 → 进程内缓存 + Redis，后台修改后主动失效
- `is_public=1` 的配置可下发给小程序端（如上传大小限制、豆换算比例）
- 所有配置修改留审计日志（谁、何时、旧值、新值）

**充值档位与会员套餐**：不塞 JSON，单独建表 `bean_package` / `member_package`，支持排序、上下架、关联订单与历史价格追溯。

> **边界说明**：服务器 CPU / 内存 / 带宽属于硬件采购，后台无法调整。后台可调的是"用多少资源"——即 `ffmpeg_concurrency`、任务超时、单任务最大时长。建议采购 **8 核 16G**，届时并发设 3–4。

## 9. 故障转移与扣豆的交互规则

| 情况 | 是否扣豆 | 说明 |
|---|---|---|
| 主通道成功 | 扣 | 按实际成本结算 |
| 备用通道成功（isFallback=1） | 扣 | 用户无感，成本可能更高，记入毛利报表 |
| 全部失败，返回兜底模板 | **不扣** | 全额解冻，前端提示"AI 服务繁忙，已为你生成基础版" |
| 请求超时 | **不扣** | 全额解冻 |
| 幂等命中（重复 requestId） | 不重复扣 | 返回首次结果 |

## 10. 告警建议

| 告警 | 触发 |
|---|---|
| 通道熔断 | 任一 provider 转 DOWN |
| 备用通道使用率过高 | 1 小时内 isFallback 占比 > 30% |
| 预算将尽 | 某 provider used / monthly > 80% |
| 毛利异常 | 当日豆消耗折算 < 当日实际 AI 成本 × 1.5 |
| 合成队列积压 | 队列长度 > 20 或平均等待 > 10 分钟 |
