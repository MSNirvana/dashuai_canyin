# 详细设计 10 · 后台前端避坑与约定

> 项目：大帅餐饮短视频创作工具　|　版本：v1.0　|　更新：2026-09-13
> 适用：`apps/admin`（React 18 + TypeScript + tdesign-react ~1.9.0 + Vite）
> 目的：记录两个会让「整页白屏 / 弹窗全空」的 tdesign 1.9.x 陷阱，以及本项目采用的统一规避方案。

---

## 1. 背景

后台 14 个页面里，一度出现过这些症状：

| 症状 | 表现 |
| --- | --- |
| 列表全空 | 「AI 场景」「AI 模型」页能打开但一条数据都没有，只弹「加载失败」 |
| 整页白屏 | `/merchants` 报 `Cannot read properties of undefined (reading '0')`；`/ai/models` 报 `reading 'code'` |
| 表头文字错乱 | 「Base URL」列头显示成空的 `<code>`，「启用」列头显示成 `<Tag>否</Tag>` |
| 弹窗全空 | 编辑弹窗能打开，但所有输入框 / 文本域都是空的（只有 placeholder） |

它们分别对应下面三个根因，其中 1 和 2 是 tdesign 1.9.x 的库行为，不是业务代码写错。

---

## 2. 坑一：BigInt 无法序列化（后端侧）

**症状**：接口 HTTP 500，前端列表全空。

Prisma 的 `BigInt` 字段（`id` / `defaultModelId` / `beanPrice` / `providerId` / `merchantId`）
无法被 `JSON.stringify` 处理，`res.json()` 会直接抛：

```
TypeError: Do not know how to serialize a BigInt
```

异常被路由的 `catch` 兜成 500，前端 `catch { message.error('加载失败') }` 后列表保持空数组。

**约定**：所有返回给后台的 Prisma 记录，一律先过一层「视图转换」把类型摊平：

| Prisma 类型 | 转换后 |
| --- | --- |
| `BigInt` | `String` |
| `Date` | `toISOString()` |
| `Decimal` | `Number` |

实现见 `server/src/services/admin-ai.service.ts` 的 `modelView()` / `sceneView()` / `callLogView()`。

---

## 3. 坑二：tdesign Table 的表头是靠 `col.render` 渲染的（前端侧）

**这是最容易踩、最难定位的一个。** 见
`node_modules/tdesign-react/es/table/hooks/useTableHeader.js` → `renderTitle()`：

```js
if (isFunction(col.title))  return col.title(params)
if (isFunction(col.render)) return col.render({ col, colIndex, row: {}, rowIndex: -1, type: 'title' })
return col.title
```

也就是说：**只要列定义了 `render`、而 `title` 不是函数，表头文案就会被 `render` 的返回值顶替**，
而且此时传进去的 `row` 是**空对象 `{}`**。由此产生两个后果：

1. **表头文字错乱** —— `{ colKey: 'baseUrl', title: 'Base URL', render: ({row}) => <code>{row.baseUrl}</code> }`
   渲染出的表头是 `<code>undefined</code>`，不是「Base URL」。
2. **整页崩溃** —— `render` 里只要解引用嵌套字段，就会在渲染表头时抛错，被 ErrorBoundary 兜住后整页白屏：
   - `row.memberships[0]` → `Cannot read properties of undefined (reading '0')`
   - `row.provider.code` / `row._count.stores` → `reading 'code'` / `reading 'stores'`

注意：**不是只有 `fixed` 列才会踩**，所有定义了 `render` 的列都会参与表头渲染。

### 规避方案

项目提供 `apps/admin/src/lib/table.tsx`：

- `cols(list)` —— 把每个列的 `title` 包装成函数，让 `renderTitle` 命中第一个分支，
  从而把 `render` 从表头渲染里彻底摘出去。这与 tdesign 自身在 `PrimaryTable.js` 中
  为 sorter / filter 列改写 `item.title` 的做法一致。
- `DataTable` —— 在 tdesign `Table` 之上自动套用 `cols()`。

**约定：后台所有表格一律用 `DataTable`，不要直接从 tdesign 引入 `Table`。**

```tsx
import DataTable from '../lib/table'

<DataTable rowKey="id" data={list} columns={[...]} />
```

## 4. 坑三：tdesign `Form.FormItem` 会把子组件的受控值抹成 `undefined`（前端侧）

**症状**：编辑弹窗里所有输入框都是空的，但 `startEdit(row)` 收到的数据完全正确。

根因在 `node_modules/tdesign-react/es/form/FormItem.js` 第 885-887 行，它会
`cloneElement` 子节点并**无条件注入** `value={formValue}`：

```js
React.cloneElement(child, { disabled, ...child.props, [ctrlKey]: formValue, onChange })
```

而 `formValue` 只在挂载时由 `getDefaultInitialData()` 求值一次（`useState` 惰性初值），
该函数在「FormItem 没有 `name`」时的兜底分支是（`hooks/useFormItemInitialData.js`）：

```js
if (typeof children !== 'function') {
  const lastChild = React.Children.toArray(children).at(-1)
  if (lastChild && React.isValidElement(lastChild)) {
    const isMultiple = lastChild.props?.multiple
    return isMultiple ? [] : initialDataMap.get(lastChild.type)   // ← 关键
  }
}
```

`initialDataMap` 里**只登记了** `Tree / Upload / Transfer / TagInput / RangeInput /
CheckboxGroup / DateRangePicker / TimeRangePicker / Checkbox` 九类组件；
`Input` / `Textarea` / `Select` / `InputNumber` / `Switch` **一律返回 `undefined`**。

于是子组件自己传的受控 `value` 被 `undefined` 覆盖 → 弹窗全空。

> 结论：tdesign 的 `FormItem` 必须配 `name`（并走 `initialData` / `form.setFieldsValue`）
> 才能工作；把它当「纯布局壳」包自管受控值的子组件，值会被静默抹掉。

### 规避方案

项目提供 `apps/admin/src/components/Field.tsx`，自绘 label + 控件布局：

```tsx
import Field, { FieldGroup } from '../components/Field'

<FieldGroup labelWidth={120}>
  <Field label="名称" required>
    <Input value={form.name} onChange={(v) => setForm(f => ({ ...f, name: v as string }))} />
  </Field>
  <Field label="分类" help="小程序首页按分类横滑">
    <Select value={form.category} onChange={...} options={...} />
  </Field>
</FieldGroup>
```

支持的 props：`label` / `children` / `labelWidth` / `required` / `status`（error/success/warning）/ `help`。

**约定：后台所有表单一律用 `Field` + `FieldGroup`，不要用 `Form.FormItem`。**
样式在 `apps/admin/src/styles.css` 的 `.form-group` / `.form-row*` 段落。

## 5. 自查清单（新增后台页面时逐条对照）

- [ ] 表格用 `DataTable`，不是 tdesign 的 `Table`
- [ ] 表单用 `Field` / `FieldGroup`，不是 `Form.FormItem`
- [ ] 列的 `render` 里对 `row` 的嵌套字段一律用可选链（`row?.a?.b`）——`DataTable` 已挡住表头调用，
      但空数据 / 脏数据仍可能进来
- [ ] 后端新增列表接口时，先写「视图转换函数」把 BigInt / Date / Decimal 摊平再返回
- [ ] 改完跑 `cd apps/admin && npx tsc --noEmit`，以及 `cd server && npx tsc --noEmit`
