# 详细设计 07 · 文案三款与分镜复杂度生成

> 项目：大帅餐饮短视频创作工具　|　版本：v1.0
> 需求：① 文案生成提供「流量款 / 介绍款 / 质量款」三选一，每款一个 Skill 提示词、后台可配；生成结果支持重新生成 / 编辑 / 复制。
> ② 自动生成分镜：按镜头复杂度产出 2~3（简单版）/ 5~6（复杂版）/ 6~9（精细版）个分镜，拆分台词片段，标注景别、建议时长、台词、画面要求，并从预置镜头库匹配基础拍摄手法；分镜支持一键复制 / 编辑 / 重新生成。

---

## 1. 文案三款

### 1.1 场景编码（后台「AI 场景」页可编辑提示词）

| 款式 | track | AI 场景 code | 定位 |
|---|---|---|---|
| 流量款 | `TRAFFIC` | `copy_traffic` | 同城引流 / 话题热度：强钩子、本地梗、低门槛行动指令 |
| 介绍款 | `INTRO` | `copy_intro` | 菜品讲解 / 套餐推广：讲清是什么、怎么吃、性价比 |
| 质量款 | `QUALITY` | `copy_quality` | 食材品质 / 匠心人设：讲来源、工艺、老板的坚持 |
| 种草型 | `RECOMMEND` | `copy_recommend` | 真实体验 / 消费决策：降低决策成本，促进收藏分享和到店 |

- 兼容旧客户端：保留 `copy_generate` 通用场景；未传 track 时按创作上已保存的款式，仍无则默认 `TRAFFIC`。
- 容错：若某款式的场景不存在或被停用，自动回退到 `copy_generate`，不会直接报错。
- 款式落库在 `creation.track`，切换款式即持久化（静默保存）。

### 1.2 提示词变量

`{{storeName}} {{category}} {{city}} {{dishName}} {{dishIntro}} {{sellingPoints}} {{persona}} {{copyText}}`
以及 `{{track}} {{trackLabel}}`。

### 1.3 计费

沿用 AI 网关既有规则：按实际成本 × 系数结算，场景 `beanPrice` 为单次冻结上限（默认 5 积分）。AI 全失败返回兜底文案且**不扣积分**。

## 2. 分镜复杂度生成

### 2.1 复杂度 → 分镜数量

| 复杂度 | complexity | 镜头数 |
|---|---|---|
| 简单版 | `SIMPLE` | 2~3 |
| 复杂版 | `COMPLEX` | 5~6 |
| 精细版 | `FINE` | 6~9 |

数量区间写入提示词变量 `{{shotCountRule}}`，AI 需严格落在区间内；复杂度落库在 `creation.complexity`。

### 2.2 分镜字段

| 字段 | 库字段 | 说明 |
|---|---|---|
| 镜头分类 | `shot_type` | 开场 / 口播 / 特写 / 原料 / 制作 / 环境 / 试吃 / 卖点 / 收尾 |
| 景别 | `shot_size` | 远景 / 全景 / 中景 / 近景 / 特写 / 大特写（本次新增列） |
| 建议时长 | `duration_suggest` | 整数秒 |
| 台词 | `line` | 口播文案的自然切分，顺序拼接可还原完整文案 |
| 画面要求 | `visual_req` | 机位 / 动作 / 光线，可照拍 |
| 匹配手法 | `library_shot_id` | 由 AI 输出的 `libraryCode` 映射到 `shot_library.id` |

### 2.3 镜头库基础手法（seed 已内置）

美食特写 `closeup_food`、老板口播 `boss_talk`、出锅装盘 `make_serve`、门店环境 `scene_ambience`、新鲜原料 `make_ingredient`、制作过程 `make_process`，
叠加原有开场 / 特写 / 制作 / 试吃 / 卖点 / 收尾共 18 条、9 类拍摄技巧。

提示词中会把整个镜头库以 `code｜名称（分类）` 逐行注入 `{{shotLibrary}}`，要求 AI 为每个分镜挑选最匹配的一条，落库后在拍摄页展示「怎么拍」。

## 3. 接口变更

| 方法 | 路径 | 变更 |
|---|---|---|
| POST | `/creations` | 入参新增 `track` / `complexity`（可选） |
| PATCH | `/creations/:id` | **新增**：保存编辑后的 `copyText` / `title` / `track` / `complexity`（不扣积分） |
| POST | `/creations/:id/copy` | 入参新增 `track`；返回新增 `track` / `trackLabel` |
| POST | `/creations/:id/storyboard` | 入参新增 `complexity`；返回新增 `complexity` / `complexityLabel` |
| PUT | `/creations/:id/shots/:shotId` | 支持编辑脚本字段 `shotType` / `shotSize` / `durationSuggest` / `line` / `visualReq`，与素材绑定字段可同时提交 |
| GET | `/creations/:id` | 每个分镜附带 `libraryShot`（匹配到的拍摄手法），并返回 `trackLabel` / `complexityLabel` |

## 4. 小程序交互

- **文案区**：三张款式卡片（流量款 / 介绍款 / 质量款）→ 生成文案；生成后展示「复制 / 编辑 / 重新生成」，编辑为行内多行文本框，保存即落库。
- **分镜区**：三张复杂度卡片（简单版 / 复杂版 / 精细版）→ 生成分镜；生成后支持「一键复制（整份）/ 重新生成」，每条分镜支持「复制 / 编辑」，编辑可改镜头分类、景别、时长、台词、画面要求。
- **拍摄页**：按分镜展示景别、建议时长、台词、画面要求，并优先展示该分镜匹配到的镜头库手法与「看示范」入口。

## 5. 本次顺带修复的缺陷

| # | 问题 | 影响 | 修复 |
|---|---|---|---|
| 1 | `findReservation` 在带 requestId 时仍用 `bizId` 兜底 | 同一创作「重新生成文案/分镜」时命中上一次预留，第二次不再冻结、结算时扣到旧预留，报 `consume/unfreeze exceeds business reservation`，接口 500 | 带 requestId 时只按 `(merchantId, bizType, requestId)` 精确匹配，`bizId` 兜底仅用于无 requestId 的历史/匿名流程 |
| 2 | `getCreation` / `submitRender` 校验素材归属时未按 id 去重 | 多个分镜复用同一段素材时，`assets.length !== assetIds.length` 误判为素材越权，导致预览与合成失败 | 先 `new Set()` 去重再比对 |
| 3 | seed 未重写 MOCK 通道密钥 | 历史密文用旧主密钥加密后无法解密，AI 调用全部失败并回落到兜底模板（不易察觉） | seed 每次重写 MOCK 密钥，保证与当前 `APP_MASTER_KEY` 一致 |
