# 自动剪辑引擎设计

## 目标

把用户上传的零散视频，稳定生成 15-60 秒的 9:16 餐饮短视频。系统需要通用支持菜品展示、探店、老板口播、门店环境和制作过程，并通过自动识别内容类型选择剪辑策略。成片质量不合格时自动重排或失败退款，不把不可播放或明显低质量的视频交付给用户。

## 选型

采用“自建确定性剪辑引擎为主链路，ChatCut 为可选回退/实验通道”。现有 RenderTask、积分冻结/结算、任务租约、COS、本地 FFmpeg、AI Gateway 和小程序轮询接口继续复用。

## 架构与数据流

1. 媒体探测：使用 ffprobe 获取显示宽高、旋转、时长、音轨和编码信息；必要时生成统一的 1080x1920 代理素材。
2. 素材分析：提取镜头边界和关键帧，计算清晰度、曝光、黑帧、抖动、响度、静音比例和重复度；AI 提取人物、菜品、门店、制作、环境、口播等语义标签。
3. 类型识别：根据整组素材推断内容类型，保留置信度；客户端可传入风格覆盖自动识别。
4. 剪辑规划：生成结构化 EDL，包含 Hook、主体、过程、结果、CTA、裁剪区间、字幕和 BGM 节奏点。AI 只产生候选，服务器校验素材存在性、时长、字幕安全区、总时长和重复率。
5. 确定性渲染：FFmpeg 负责缩放、裁切、硬切/轻转场、字幕、音频混合、响度归一化和封装；Remotion 仅用于需要可复用动效模板的包装层。
6. 自动验收：检查文件可解码、音画时长、比例、黑帧、字幕越界、音频峰值、文件大小和输出时长。失败时重新规划一次；仍失败则执行统一退款流程。

## 质量策略

候选镜头评分为：画面质量 25%、内容相关性 25%、叙事价值 20%、稳定性 15%、音频质量 10%、与相邻镜头互补性 5%。开头优先选择 1-3 秒内主体明确且有明显视觉变化的镜头；素材不足时缩短成片，不用低质量片段填充。

策略 profile 统一由引擎执行：DISH/EXPLORE 偏成品特写和过程，TALKING_HEAD 由语音区间驱动剪辑并去除重复停顿，VENUE 偏空间建立和慢节奏，MIXED 使用 Hook -> 主体 -> 过程 -> 结果 -> CTA。无法判断时使用 MIXED 并记录低置信度。

## 任务与回退

RenderTask 的 `paramsJson` 保存 engine、profile、analysis、edl、quality 和 attempt 快照。默认 engine 为 LOCAL；显式配置或本地质量失败时才进入 CHATCUT。所有终态仍由现有 `completeRender`/`failRender` 负责，旧 owner 使用租约 fencing 不能覆盖新执行者。

## 成本、隐私与限制

AI 只处理关键帧和必要的转录文本，不把原始素材长期发送给外部服务。分析和规则规划失败时使用无 AI 的保守 EDL。单任务限制素材数量、总时长和最大磁盘占用，超限在冻结积分前拒绝。

## 验收

- 本地引擎可在无 ChatCut 配置时完成真实成片；
- 失败必退款，成功只结算一次；
- 9:16 输出可被 ffprobe 解码，时长在 15-60 秒或素材实际总时长范围内；
- 低质量、黑帧、字幕越界、音画不同步不会交付；
- AI Gateway 不可用时仍可规则降级出片；
- 现有 EDL、旋转、缓存、租约和多档计费验证脚本保持通过。
