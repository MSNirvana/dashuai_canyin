# 大帅餐饮小程序全流程 UI 与交互重构设计

## 目标

把当前“页面功能都在，但信息互相抢位置”的小程序，重构成面向餐饮商家的品牌内容产品：内容图片和视频优先，操作路径短，用户随时知道当前阶段、下一步和失败后的恢复方式。

本次不改变现有业务接口、数据模型、登录方式、渲染引擎和微信页面路由；重点重做信息架构、共享视觉令牌、页面层级、操作反馈和合成/成片流程。

## Design Read

这是面向餐饮商家的高频内容生产工具，采用品牌消费产品语言：图片/视频先行、轻量分层、强反馈和少量情绪化品牌红。整体接近内容创作产品，而不是后台管理台；同时保留专业生产工具所需要的明确状态、可回退路径和任务可见性。

设计参数：`DESIGN_VARIANCE 7`、`MOTION_INTENSITY 5`、`VISUAL_DENSITY 4`。

## 体验原则

- 每页只保留一个主任务和一个主按钮，次要动作降级为轻按钮、图标按钮或页面菜单。
- 任何页面都明确显示当前阶段、完成状态和下一步；错误必须贴近发生位置并提供恢复动作。
- 页面分区替代“每块内容一个卡片”，只有重复对象、媒体预览、弹层和需要边界的工具才使用卡片。
- 视频/图片是内容中心：使用稳定比例、清晰缩略图、状态角标和可预览反馈，不用长段说明文字代替内容。
- AI 默认模式只展示决策摘要；高级模式才展示可调参数，并用折叠区收纳低频设置。
- 动效只服务于阶段切换、上传完成、生成进度和成功反馈；不使用持续漂浮、装饰光晕或大面积渐变。

## 信息架构

### 底部导航

保留 `首页 / 创作 / 我的` 三个 Tab，但重新定义职责：

- `首页`：灵感流、最近创作、当前门店摘要和单一“开始创作”入口。
- `创作`：创作项目列表、项目状态和新建项目入口。
- `我的`：账户、门店、菜品、积分、教学和历史作品的分组入口。

门店与菜品不再和首页主任务并列展示；通过“我的”或创作上下文进入，减少首页首屏的选择压力。

### 创作主流程

创作页面顶部使用四段式阶段指示：

`主题 → 素材 → 剪辑 → 发布`

当前阶段高亮，已完成阶段可回看，未完成阶段显示缺少条件。阶段之间使用现有页面路由，不新增业务实体；只统一入口、返回、完成和异常状态。

## 页面设计

### 首页

- 首屏只保留品牌/内容视觉、当前门店摘要和一个“开始创作”主按钮。
- 最近创作使用横向媒体卡，显示封面、状态和最后更新时间；不把完整错误、积分和操作按钮全部展开。
- 优秀作品变成可筛选的内容流，分类使用横滑标签，播放/查看是卡片主动作。
- 门店切换收进顶部轻量入口；账户和积分不再占据首屏主视觉。
- 加载、空状态和网络错误使用统一媒体占位与单一重试动作。

### 创作列表 / 创作编辑 / 分镜素材

- 列表页采用“项目封面 + 标题 + 当前阶段 + 一个继续按钮”的纵向结构，删除同一张卡片里的重复操作。
- 编辑页把主题、口播文案、平台方向组织成三个短区块；高级说明进入帮助弹层。
- 分镜页使用大缩略图网格/列表切换：上传、替换、预览、跳过和重试都绑定在单个分镜上下文内。
- 底部固定操作栏只保留“上一步”和当前阶段主操作；上传进行中时显示进度和剩余数量，不让按钮失去反馈。

### 合成成片

这是本次优先级最高的页面，改为“预览优先、设置后置”的结构：

1. 顶部：创作标题、当前门店和返回创作入口。
2. 主舞台：固定比例视频预览/素材预览；没有可预览媒体时显示明确的补素材状态。
3. 生成区：档位、预计积分、当前任务状态和唯一主按钮。生成中只展示进度、阶段文案和可离开提示。
4. 剪辑偏好：默认折叠，展示当前 AI 决策摘要；高级模式展开配音、字幕、节奏、转场、音量和备注。
5. 历史任务：移出当前生成区，使用单独的“历史成片”折叠区，只显示状态、时间和查看入口。
6. 发布素材：不在合成页展开标题/封面/文案，生成后进入成片交付页。

合成页首屏只回答：当前素材是什么、会生成什么、需要多少积分、点击哪里开始。

### 成片交付页

- 视频作为唯一主视觉，使用稳定竖屏舞台；状态未完成时不渲染空播放器。
- 完成后第一组操作为“保存到相册”和“分享/复制链接”，避免和文案操作混在一起。
- 封面、标题、文案以交付顺序排列：封面预览 → 标题复制 → 文案复制。
- 失败状态集中在视频舞台下方，显示原因、重试和返回编辑；不与历史任务、积分说明并列竞争。
- 重新生成使用同一创作上下文返回合成页，保留上次设置快照。

### 我的 / 门店 / 菜品 / 个人资料

- “我的”按 `账户与权益 / 我的内容 / 经营资料 / 帮助与协议` 分组。
- 门店列表突出门店图片、名称、城市和当前选中态；创建/编辑表单按“基本信息 → 位置 → 图片”分段。
- 菜品列表突出封面、名称、价格和媒体数量；菜品详情优先展示封面、图片视频媒体和核心信息。
- 个人资料只保留头像、昵称、积分/订阅摘要和设置入口，避免重复展示账户状态。

## 共享设计系统

保留 TDesign 组件和现有品牌红，但建立小程序专用的页面令牌：

- 背景：页面浅灰、内容白、媒体舞台黑；品牌红只用于主按钮、选中态、进度和危险确认。
- 类型：页面标题、区块标题、正文、辅助信息、状态标签五级；减少同屏不同字号。
- 间距：以 8rpx 为基准，页面水平边距统一；固定底栏预留安全区域，避免遮挡内容。
- 圆角：媒体舞台与主要内容 20~28rpx，小控件 12~16rpx；取消无意义的大圆角嵌套。
- 状态：统一加载、空、错误、成功、上传中、生成中组件，文字和动作位置固定。
- 操作：每页一个主按钮；图标按钮使用 TDesign 图标并提供明确的辅助文本/点击区域。

## 兼容与数据边界

- 保留现有页面路由和服务接口，不改变 RenderTask、Creation、Store、Dish 数据结构。
- 旧任务没有新 UI 快照字段时使用默认展示，不阻断历史任务查看。
- 当前合成引擎、AI 默认/高级模式、字幕与配音逻辑保持服务端行为不变；UI 只重新组织表达和入口。
- 现有后台管理端不纳入本次小程序改造，避免混淆两套产品的用户目标。

## 实施顺序

1. 共享令牌、页面外壳、底栏安全区、按钮/状态/空状态组件。
2. 合成页和成片交付页，优先解决信息杂乱和任务反馈。
3. 首页与创作四阶段入口，统一主流程和回退关系。
4. 分镜素材、门店、菜品、我的页面迁移到新组件和间距规范。
5. 全量微信构建、真机/开发者工具流程回归和关键页面截图检查。

## 验收标准

- 首页、创作、合成、成片、我的五个核心入口不存在多个同等级主按钮。
- 合成页首屏不同时展示历史任务、发布素材和全部高级参数；默认模式一屏可理解并提交。
- 成片页首屏能完成播放、保存/分享，失败状态能在同页重试或返回编辑。
- 页面在常见微信手机尺寸下无底栏遮挡、按钮溢出、文字重叠或空播放器假象。
- 交互状态覆盖加载、空数据、上传中、生成中、成功、失败和重试。
- `apps/mini` 类型检查、微信构建和 `verify-weapp-dist` 通过；不启动本地后端，不改变服务端部署配置。
