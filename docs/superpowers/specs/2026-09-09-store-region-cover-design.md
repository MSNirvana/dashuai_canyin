# 门店全国地区与主图功能设计

## 背景与目标

当前小程序的门店编辑页只写死了 10 个城市，无法覆盖实际经营地区；门店也没有独立主图，导致“我的门店”列表识别度不足。

本次改造完成两个目标：

1. 门店地址支持中国大陆、香港、澳门、台湾的省/地区、市、区县三级联动选择。
2. 每个门店支持一张主图，并可在编辑页上传、更换、删除，在“我的门店”列表展示。

不在本次范围内：地图定位、经纬度、街道四级数据、多图相册、图片裁剪、COS 物理删除及后台管理端门店图片展示。

## 方案选择

地区数据采用随小程序打包的静态数据，不依赖运行时网络接口。数据源使用固定版本的 `@vant/area-data`，其数据覆盖中国大陆、香港、澳门、台湾，体积小于完整行政区查询类数据包，并采用 MIT 许可证。依赖版本必须锁定；升级时通过正常依赖升级更新地区数据。

未采用平台原生地区选择器，因为微信、抖音和支付宝小程序的数据范围及港澳台表现可能不一致。未采用服务端地区接口，因为当前需求不需要动态运营地区数据，引入接口、缓存和失败状态会增加不必要复杂度。

## 地区选择设计

### 数据适配层

在小程序内新增独立地区数据模块，将 `@vant/area-data` 的省、市、区县 code map 转换为页面需要的三级级联结构。页面只依赖以下稳定接口：

- 根据省级 code 获取城市列表。
- 根据城市 code 获取区县列表。
- 根据已保存的省、市、区县名称恢复选择索引。
- 返回当前选择对应的省、市、区县名称。

地区 code 只用于前端联动，不新增数据库字段。数据库继续保存可读名称。直辖市保持三级结构，例如“北京市 / 北京市 / 朝阳区”；香港、澳门、台湾按照数据源提供的三级结构展示。

### 页面交互

门店编辑页使用三列联动选择器，顺序为“省/地区、城市、区县”。表单内显示完整的已选结果。

- 新建门店默认未选择地区，不擅自选择用户所在地。
- 省/地区变化时，城市切到该省的第一项，区县同步切到该城市第一项。
- 城市变化时，区县切到该城市第一项。
- 保存时同时提交 `province`、`city`、`district`。
- 已有门店缺少 `province` 时，数据适配层尝试按城市和区县反查；无法唯一匹配时保留旧文本，并要求用户重新选择后才会覆盖。
- 现有三个字段仍为可选项，未选地区不阻止保存门店。

## 门店主图设计

### 数据模型与接口

`Store` 新增可空字段：

```text
coverKey String? @map("cover_key") @db.VarChar(512)
```

新增 Prisma migration。门店列表和详情接口返回 `coverKey`，更新接口接受 `coverKey`；新建门店的图片在取得门店 ID 后通过更新接口关联。服务端请求校验限制长度不超过 512。非空 key 必须符合当前商户上传目录 `uploads/{merchantId}/`，并且必须对应当前门店下已完成的图片 `MediaAsset`，防止引用其他商户、其他门店或非图片素材。

清除主图使用显式 `null`，因此前后端输入类型必须区分：

- `undefined`：本次请求不改变主图。
- 非空字符串：设置或更换主图。
- `null`：清除主图。

### 编辑页交互

图片区域位于门店基本信息之前，展示固定比例预览。无图时显示简洁占位和上传入口；有图时显示“更换”和“删除”。一次只能选择一张压缩图片，可从相册或相机选择。

选择图片后先显示本地临时预览，点击保存时再上传，避免用户取消编辑后立即产生无用素材。上传期间禁用重复保存并显示进度。

保存顺序：

- 编辑已有门店：上传新图（如有），随后一次更新门店资料和 `coverKey`。
- 新建门店且无图片：直接创建门店。
- 新建门店且有图片：先创建门店取得 `storeId`，再使用该门店 ID 上传图片，最后更新 `coverKey`。这是现有上传接口进行门店归属校验所必需的顺序。

新建门店时，如果门店创建成功但图片上传或二次更新失败，不回滚或删除已创建门店。页面明确提示“门店已创建，图片保存失败”，并返回列表；用户可重新进入编辑页补传，避免自动删除首个默认门店或制造跨 COS/数据库的伪事务。

删除图片只在保存时将 `coverKey` 清空。本次不物理删除 COS 对象或 `MediaAsset` 记录，避免误删仍被其他历史内容引用的资源；孤立素材清理由后续独立资源治理处理。

### 列表展示

“我的门店”卡片增加固定尺寸主图区域，避免图片加载导致布局跳动。列表接口返回 `coverKey` 后，小程序复用现有 `/media/play-url?key=...` 接口获取一小时有效的签名 URL，并并行加载最多 10 家门店的图片。

- 有可用 URL：使用 `aspectFill` 展示。
- 无主图、签名失败或本地未配置 COS：展示固定占位，不影响门店选择、编辑、菜品和删除操作。
- 地区摘要改为按 `province / city / district` 去重后展示，避免直辖市出现重复的“北京市 · 北京市”。

## 安全与错误处理

- 服务端更新验证 `coverKey` 的商户前缀、门店归属、素材类型和完成状态，客户端校验不作为安全边界。
- 上传继续复用现有 STS 临时凭证、COS SDK 和 `/upload/complete` 落库流程，不新增长期密钥。
- 图片选择取消不显示错误；上传、签名和保存失败使用明确提示。
- 上传或保存进行中禁止重复提交。
- 旧门店的空地区、空图片和部分地区字段保持兼容，不能导致页面白屏。
- 本地未配置 COS 时保持现有演示态：签名 URL 为 `null`，列表显示占位图。

## 修改范围

- 小程序门店编辑页与样式。
- 小程序门店列表页与样式。
- 小程序门店 API 类型、图片签名调用和地区数据适配模块。
- 小程序依赖及锁文件。
- 服务端门店路由、服务与 Prisma schema/migration。
- 聚焦本功能的服务端和前端测试；不做无关页面重构。

## 验收标准

1. 新建和编辑门店均可选择中国大陆、香港、澳门、台湾的三级地区并正确回填。
2. 切换上级地区后，下级选项不会保留不属于当前上级的旧值。
3. 旧门店即使缺少省份也可打开、编辑和保存。
4. 门店主图可上传、更换、删除，重新进入编辑页后状态正确。
5. 新建门店带图片时，图片与新门店建立正确归属。
6. “我的门店”每张卡片展示对应主图；无图或无 COS 配置时展示稳定占位。
7. 伪造其他商户、其他门店或非图片素材的 `coverKey` 会被服务端拒绝。
8. 默认门店、门店数量限制、门店切换、菜品入口和删除规则不发生回归。
9. Prisma 校验/生成、服务端 typecheck、小程序 typecheck 和微信小程序构建全部通过。
