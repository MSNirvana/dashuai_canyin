# 登录浮层与本地接口配置设计

## 目标

移除小程序首屏登录体验，允许用户先进入首页和创作页。用户点击底部“我的”时，如果本地没有有效登录态，在当前页面显示带半透明遮罩的居中登录浮层；登录成功后关闭浮层、刷新账户数据并继续停留在“我的”页面。

同时修复本地构建使用生产占位域名的问题，确保本地一键登录请求发送到运行中的服务端。

## 方案

沿用现有登录 API、merchant store 和登录错误处理，不新增认证协议。登录页组件不再作为首屏路由使用，登录交互在“我的”页面以内嵌受控浮层承载；这样登录状态变化不需要页面跳转，也不会改变现有 tabBar 栈。

本地开发脚本显式使用 `NODE_ENV=development`，默认解析为 `http://localhost:3000/api/v1`。生产地址继续保留为环境占位值，并要求通过 `TARO_APP_API_BASE_URL` 显式注入，避免误把本地配置发布为线上配置。

## 交互与数据流

1. 小程序启动时照常 hydrate merchant store。
2. 点击底部“我的”后进入 `pages/mine/index`。
3. 页面展示前检查 store 中的 token；无 token 时设置 `showLogin=true`。
4. 浮层显示品牌、微信一键登录按钮和关闭按钮；本地开发模式额外显示开发登录按钮。
5. 微信登录调用 `Taro.login` 与 `authApi.wechatLogin`，成功后调用 `setLogin`，关闭浮层并刷新 `refreshMe`。
6. 用户关闭浮层时仍停留在“我的”页面，页面显示未登录状态；后续再次进入“我的”时再次检查并提示登录。
7. 已有 token 时不显示浮层，继续执行原账户数据刷新流程。

## 组件边界

- `pages/mine/index.tsx` 负责登录浮层的显示状态、登录回调和页面刷新。
- `pages/mine/index.scss` 负责遮罩、弹层和按钮样式，保持现有设计变量。
- `services/auth.ts` 保持接口封装不变。
- `config.ts` 只调整本地/生产 API 地址选择逻辑。
- `app.config.ts` 移除登录页路由，避免用户从首屏进入独立登录页。

## 错误处理

- 用户拒绝手机号授权时显示现有提示，不关闭浮层。
- 网络或后端错误显示现有错误文本，允许重新点击登录。
- 登录请求期间禁用按钮并显示“登录中…”，防止重复提交。
- 关闭浮层不清除已有 token，也不触发导航。

## 验证

- `npm run typecheck`（小程序）。
- `npm run build:weapp`，确认 `dist/weapp/app.json` 生成且不含登录首屏路由。
- 检查本地构建产物中的 API 基址不再是 `replace_me.example.com`。
- 保持服务端 `/healthz` 与管理后台可访问。
