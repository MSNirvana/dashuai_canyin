# 菜品多媒体与详情页设计

## 目标

菜品支持最多 3 张图片和 3 个视频。上传成功后立即显示预览；第一张图片始终作为封面。菜品列表展示封面，点击进入只读详情页，详情页可进入编辑。

## 数据与兼容

保留 `Dish.coverKey` 与 `Dish.videoKey` 兼容历史数据。新增 `DishMedia` 关联记录保存菜品媒体的 `assetId`、类型和顺序；保存时服务端校验媒体归属当前商户和门店、状态为 READY，并限制每类最多 3 条。第一张图片同步写入 `coverKey`，第一条视频同步写入 `videoKey`。

## 前端流程

编辑页维护图片和视频数组，上传按钮在达到 3 个时禁用。图片显示缩略图，可预览和删除；视频显示封面或占位卡并可播放。删除后重新计算封面。保存提交有序媒体列表及兼容字段。列表卡片点击进入详情，删除操作阻止冒泡。详情页展示文字、全部图片和视频，并提供编辑按钮。

## 地址与错误处理

媒体通过现有上传接口上传，通过 `/media/:assetId/play-url` 或按 key 的播放接口获取临时 URL；本地开发继续使用本地签名 URL。上传失败、媒体越权、数量超限均显示明确提示，页面加载失败显示空状态而不白屏。

## 验收标准

- 图片和视频分别最多 3 个，超出不发起上传请求。
- 上传完成后编辑页可看到图片缩略图和视频卡片。
- 首图作为列表封面；删除首图后下一张自动补位。
- 列表点击进入详情，详情可查看全部媒体并返回编辑。
- 历史只有 `coverKey`/`videoKey` 的菜品仍可查看和编辑。
- `npm run typecheck` 与 `npm run build:weapp:dev` 通过，构建产物不含 `jsxDEV` 或占位 API 地址。
