## 一、框架梳理：海外 AI 接入与备案合规

### 1.1 结论先行

**不需要两套业务服务器。** 只需要：**国内主服务器（唯一业务后端）+ 一个轻量 AI 出口通道**。

| 问题 | 答案 |
|---|---|
| 小程序 API 域名必须备案吗？ | **是**。微信小程序 request 合法域名要求 HTTPS 且域名已 ICP 备案 |
| 备案要求服务器在国内吗？ | **是**。ICP 备案需通过大陆云服务商接入（阿里云/腾讯云大陆节点），服务器物理上须在境内 |
| 那海外 AI（OpenAI/Claude/Gemini）怎么办？ | 国内服务器无法直连。两条路：**商业中转站 API** 或 **自建海外中转节点**，见 1.2 |
| 文案/分镜生成必须海外 AI 吗？ | **不必**。国产模型（DeepSeek/通义/豆包/混元）的中文营销文案质量完全够用，且合规成本为零 |

### 1.2 AI 出口通道两个方案

**方案 A：商业中转站 API（推荐起步）**
- 市面上有大量 OpenAI 兼容协议的中转服务，买额度即可用
- **我们代码零改动**：`server/src/ai/adapters.ts` 的 `openaiCompatible` 适配器就是 OpenAI 协议，管理后台新建 Provider，`baseUrl` 填中转站地址、填 apiKey 即可
- 优点：最快上线、无运维
- 缺点：第三方稳定性/隐私不可控，适合早期验证

**方案 B：自建海外中转节点（推荐规模化后）**
- 香港/新加坡 VPS 上部署 OneAPI / NewAPI / LiteLLM Proxy，只做协议转发
- 国内服务器 → 中转节点 → OpenAI/Anthropic 官方 API
- 优点：密钥自己管、可加缓存限流、稳定可控
- 缺点：多一台机器的运维成本（很轻，纯转发，1C1G 足够）

### 1.3 合规注意（重要）

- **《生成式人工智能服务管理暂行办法》**：向境内公众提供生成式 AI 服务，需做安全评估与算法备案。小程序直接把 AI 生成内容展示给 C 端用户，正式商用时这是硬要求。
- **最省事的合规路线**：主力模型用**国产已备案大模型**（DeepSeek、通义、豆包、混元——我们 adapter 全部支持），AI 生成内容直接面向用户；海外模型经中转只做**内部辅助**（提示词优化、文案审校），其输出不直接展示给用户。这样备案义务落在模型厂商侧，我们作为接入方风险最小。
- 海外模型输出直接给 C 端用户展示的路线，商用前建议咨询法务。

### 1.4 现有代码就绪度：已就绪 ✅

```
小程序 → 国内主服务器(API, 备案域名)
              ├─ AI网关(gateway.ts) ──→ Provider A: DeepSeek(直连, 国产)
              │                      ├→ Provider B: 通义(直连, 国产)
              │                      └→ Provider C: 中转站(OpenAI兼容) ──→ 海外AI
              ├─ FFmpeg Worker(粗剪/AI合成)
              └─ MySQL / Redis / COS
```

- `AiProvider.baseUrl` 每个供应商独立配置，管理后台可直接加
- 网关已具备：候选模型 fallback、熔断器、月度预算控制、调用日志、成本核算
- 切换供应商/中转站**不改一行代码**，纯后台配置

TypeScript 检查：server 0 错误、mini 0 错误。

### 2.2 本轮发现并已修复的 bug

#### Bug 1（P0·计费漏洞）：未裁剪素材合成几乎免费

**问题链**：
1. `shots.tsx` 上传素材时从不设置 `trimStartMs/trimEndMs`（现状所有用户素材都未裁剪）
2. 上传确认也不上报 `durationMs`，`MediaAsset.durationMs` 全是 null
3. `submitRender` 计费只算 trim 区间：未裁剪 = 0 秒 → `max(1, ceil(0×1))` = **只扣 1 豆**
4. 但 FFmpeg worker 对未裁剪素材用**全片**（`endMs>startMs` 才加 `-to`），实际成片可能是 60 秒
5. 结果：用户可得到任意时长的 AI 配音成片，只付 1 豆；前端预估却显示 20+ 豆（预估和实扣还不一致）

**修复**（本轮已完成并验证）：
- `RenderClip` 新增 `durationMs`（素材时长随任务快照）
- 计费时长 = trim 优先，无 trim 用素材时长（与 FFmpeg 行为严格一致），见 `clipDurationMs()`
- 素材既无 trim 又无时长 → 拒绝提交（业务码 4009），杜绝无法计价的合成
- `shots.tsx` 现在上报 `chooseMedia` 的 `duration`（秒×1000）和 `size`（真实字节数，之前写死 0）
- `compose.tsx` 预估逻辑与后端对齐：trim 优先 → 素材时长 → AI 建议时长兜底；只计已上传素材的分镜
- `getCreation` 接口给每个分镜附加 `assetDurationMs`

**验证结果**：
- e2e（6镜×3s trim）：18 豆 ✅
- 无 trim + 10s 素材 ×6 镜：FULL 60 豆 ✅、RECOLOR 30 豆 ✅
- 无时长素材：4009 拒绝 ✅

#### Bug 2（P1）：RECOLOR 与 FULL 同价

**问题**：注释和常量都说 RECOLOR=10 豆，实际计费只按时长，RECOLOR 也是全价。`RENDER_BEAN_RECOLOR` 常量定义了从未使用。

**修复**：RECOLOR 按 `render.recolor_ratio`（系统配置，默认 0.5）折扣计价——依据是重调色可复用归一化缓存（省掉源解码+缩放这个最贵的环节）。已验证 60s 成片 RECOLOR 扣 30 豆。

#### Bug 3（P2）：并发提交竞态

**问题**：「已有任务进行中」检查与建任务之间无锁，两个并发请求可同时通过检查，创建两个任务、双重冻结积分。

**修复**：检查+建任务放进同一事务，先 `SELECT ... FOR UPDATE` 锁创作行，序列化同一创作的并发提交。

## 三、三档视频生成模式设计（基础 / AI / 精品）

### 3.1 产品定义

| 档位 | 引擎 | 内容 | 出片速度 | 计费建议 | 对应现状 |
|---|---|---|---|---|---|
| **基础生成** | 后台 FFmpeg 粗剪 | 归一化+按序硬切拼接+调色，无配音无字幕 | 秒~分钟级 | `point_per_sec × 1.0` | ≈ 现有 `aiMode=false` |
| **AI 生成** | FFmpeg + AI Skill 全管线 | 粗剪 + AI 配音(TTS) + 字幕 + 智能节奏（后续：BGM 智能选择、节奏点检测、自动卡点） | 分钟级 | `point_per_sec × 1.5` | ≈ 现有 `aiMode=true` |
| **精品生成** | 人工剪辑 | 剪辑师精剪、调色、配乐、包装，成片上传回传用户 | 小时级（SLA 承诺） | 高价固定档或 `× 3.0` | **全新，需开发** |

### 3.2 「AI 生成配备一整套 Skill」的落地方式

在我们现有架构里，"Skill" = **AiScene 场景管线**（后台可配提示词/模型/重试/预算），无需引入新框架：

```
现有场景：copy_generate（文案）、storyboard_generate（分镜）
建议新增场景（每步独立计费、独立模型、独立 fallback）：
  script_polish    → 文案润色成口播稿（按分镜时长控制字数）
  bgm_select       → 按菜品/情绪选 BGM 曲目（输出曲库 ID）
  rhythm_detect    → 节奏点检测参数（供 FFmpeg 卡点）
  title_overlay    → 生成封面标题/贴片文案
  review_guard     → 内容安全审校（过滤违规词后再配音）
```

worker 侧在 `applyAiSynthesis` 前后逐步接入这些场景输出，每一步都是独立 AiScene，坏了对整链路无阻塞（网关已支持降级）。

### 3.3 精品生成（人工剪辑）落地方案

**核心思路**：复用 RenderTask 状态机，PREMIUM 任务**不进 FFmpeg worker 队列**，进人工生产队列；管理后台是剪辑师工作台。

**数据模型改动（schema.prisma）**：
```prisma
model RenderTask {
  // 新增：
  grade        String  @default("AI") @db.VarChar(16)  // BASIC / AI / PREMIUM（产品档位）
  // status 枚举扩展：QUEUED → RUNNING → SUCCESS / FAILED 之外新增：
  //   MANUAL_PENDING（待人工接单）→ MANUAL_DOING（剪辑中）→ 上传成片 → SUCCESS
  assignedAt   DateTime?  // 剪辑师接单时间
  deadlineAt   DateTime?  // SLA 截止（如 48h），超时告警
}
```

**关键决策**：保留 `mode`(FULL/RECOLOR) 表达技术语义、新增 `grade` 表达产品档位，互不干扰，老数据无需迁移（默认 AI）。

**流程**：
1. 小程序提交合成时选档位（三张卡片，见 3.4）
2. `submitRender`：grade=PREMIUM → 冻结积分（按时长×3 或固定档价）→ 状态 `MANUAL_PENDING`
3. FFmpeg worker 轮询条件加 `grade != PREMIUM`（跳过人工任务）
4. 管理后台「剪辑工作台」（扩展现有 RenderTasks 页）：
   - 待接单列表（含 SLA 倒计时）→ 接单（`MANUAL_DOING`）
   - 素材打包下载（复用 COS 签名 URL，按 clips 列出）
   - 剪辑完成：上传成片到 COS + 填 resultKey → 调用结算接口
5. 后端新增管理路由：`POST /admin/api/v1/render-tasks/:id/claim`（接单）、`/deliver`（交付成片，事务内 consume 结算 + 状态 SUCCESS）
6. 小程序轮询到 SUCCESS 正常播放（对用户透明，和机器合成无差别）
7. 超时未交付：`MANUAL_PENDING/MANUAL_DOING` 超过 deadlineAt → 定时任务自动 unfreeze 退款 + FAILED(超时)

### 3.4 小程序端改动（compose 页）

把现在的「AI 合成开关」升级为**三选一卡片**：

```
┌─────────────┐ ┌─────────────┐ ┌─────────────┐
│ 基础生成     │ │ AI 生成      │ │ 精品生成     │
│ 粗剪拼接+调色 │ │ 配音+字幕+节奏│ │ 人工精剪     │
│ 秒级出片     │ │ 分钟级出片   │ │ 48h 内交付   │
│ ~60 积分     │ │ ~90 积分    │ │ ~180 积分    │
└─────────────┘ └─────────────┘ └─────────────┘
```

- `submitRender` 请求体新增 `grade` 字段（后端 zod 校验，默认 AI 兼容旧客户端）
- 调色滑杆仅基础/AI 档显示（精品档由剪辑师把控）
- PREMIUM 提交后文案提示「已进入人工剪辑队列，完成后将通知你」——后续可接微信订阅消息

### 3.5 计费方案

```
基础 = ceil(总秒数 × point_per_sec × 1.0)
AI   = ceil(总秒数 × point_per_sec × 1.5)
精品 = ceil(总秒数 × point_per_sec × 3.0)   // 或固定档位价（99/199/399 积分），后台可配
```

三个系数全部走 system settings（`render.grade_ratio_basic/ai/premium`），运营可随时调价。

### 3.6 实施顺序建议

1. **P0（先上线的最小闭环）**：基础 + AI 两档——现有代码 90% 就绪，主要是把 `aiMode` 布尔升级为 `grade` 字段 + 小程序三卡片 UI（含精品置灰「敬请期待」）
2. **P1**：精品生成后端状态机 + 管理后台剪辑工作台
3. **P2**：AI Skill 场景扩展（bgm_select → rhythm_detect → title_overlay 逐个上）
4. **P3**：订阅消息通知（合成完成/精品交付提醒）

## 五、三档生成实施记录（2026-09-08 当日完成）

### 5.1 数据模型

`RenderTask` 新增：`grade`（BASIC/AI/PREMIUM，默认 AI，老数据自动归为 AI）、`assignedAt`（剪辑师接单时间）、`deadlineAt`（SLA 截止），新增索引 `(grade, status)` 支撑人工队列查询。技术语义（FULL/RECOLOR）保留在 `paramsJson.mode`，与产品档位互不干扰。

### 5.2 提交与计费

- 提交入参新增 `grade`；旧客户端只传 `aiMode` 的自动推导（false→BASIC，其余→AI），完全向后兼容
- 计费 = `ceil(时长 × point_per_sec × 档位系数 × [RECOLOR 再乘 recolor_ratio])`
- 档位系数走 system settings：`render.grade_ratio_basic/ai/premium`（默认 1 / 1.5 / 3，运营可调）
- PREMIUM 提交后进入 `MANUAL_PENDING`，写入 `deadlineAt = now + render.premium_sla_hours`（默认 48h）；无论演示/真实环境都不模拟成功
- 并发拦截扩展到人工状态：QUEUED/RUNNING/MANUAL_PENDING/MANUAL_DOING 任一存在即拒绝重复提交

### 5.3 状态机（PREMIUM）

```
MANUAL_PENDING（待接单）→ MANUAL_DOING（剪辑中）→ SUCCESS（交付结算）
                    ↘ 任意阶段可标记失败 → FAILED（unfreeze 全额退款）
超时未交付（deadlineAt 已过）→ FAILED(SLA_TIMEOUT) + 自动退款（sweeper 每 5 分钟扫描）
```

### 5.4 精品链路（`server/src/render/premium.ts`）

- `claimPremiumTask`：接单（updateMany 条件更新防并发双接）
- `deliverPremiumTask`：交付成片（复用 completeRender：consume 结算 + 落产物，幂等）
- `failPremiumTask`：人工终止（unfreeze 退款 + FAILED/MANUAL_FAILED）
- `premiumMaterials`：素材清单 + COS 签名下载链接（管理员可信通道）
- `startPremiumSweeper`：SLA 超时 sweeper，随 API 服务常驻（不受 FFMPEG_WORKER 开关影响）

FFmpeg worker 轮询条件改为 `grade != PREMIUM`，人工任务不会进机器队列。

### 5.5 管理端点（`/admin/api/v1/render/tasks`）

- `GET ?status=&grade=`：任务列表（新增档位筛选）
- `POST /:id/claim`：接单
- `POST /:id/deliver`：交付成片 `{ resultKey, previewKey?, durationMs? }`
- `POST /:id/fail`：标记失败退款 `{ reason }`
- `GET /:id/materials`：素材清单 + 签名下载链接

### 5.6 小程序合成页

- 「AI 合成」开关升级为三选一卡片：**基础生成（快）/ AI 生成（推荐）/ 精品生成（精，金色选中态）**
- 精品档：隐藏调色滑杆（由剪辑师把控），显示金色说明条（人工队列 + 超时自动退款承诺）
- 提交后不轮询（人工交付以页面刷新为准），进行中任务按钮置灰显示「人工剪辑进行中」
- 「仅调色重生成（5 折）」按钮文案同步更新

### 5.7 管理后台剪辑工作台（RenderTasks 页）

- 档位列 + 档位/状态筛选 + SLA 剩余倒计时列
- PREMIUM 待接单/剪辑中任务行内操作：**接单 / 素材 / 交付 / 失败退款**
- 交付弹窗：成片 COS Key（默认按 `renders/{merchantId}/{taskId}.mp4` 预填）、封面 Key、时长
- 素材弹窗：各分镜口播文案、时长、签名下载链接（1 小时有效）
