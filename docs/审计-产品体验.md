# 餐饮短视频创作小程序：产品与体验审计

> 审计范围：`apps/mini` 小程序、`apps/admin` 运营后台、`docs/04-页面流程与验收.md`、`docs/05-计费规则.md`、`docs/06-全链路梳理与三档生成方案.md`，并抽查相关服务接口。审计方式为只读静态审视，不替代真机、微信支付、COS、FFmpeg 和 TTS 线上验收。
>
> 证据边界：以下“现状”仅指代码/文档中可确认的行为；不能从静态代码确认的内容明确标注为“待真机/联调验证”。

## 1. 结论摘要

### 1.1 当前产品定位

产品定位是面向餐饮商家的微信小程序创作工具，以“门店/菜品/老板人设”等经营资料为输入，帮助商家完成 AI 口播文案、AI 分镜、分镜素材上传、基础/AI/精品三档成片输出，并配套积分、订阅和后台运营配置。产品不是通用剪辑器，而是“餐饮经营内容资产 + AI 脚本 + 低门槛拍摄 + 自动成片”的垂直生产工具。

代码证据：

- 登录页将产品描述为“商家短视频创作工具”，能力为“AI 写文案 · 分镜脚本 · 一键出片”：`apps/mini/src/pages/login/index.tsx:90-94`。
- 首页核心功能为我的创作、门店管理、菜品库、老板人设：`apps/mini/src/pages/home/index.tsx:108-137`。
- 创作模型包含门店、菜品、赛道、复杂度和分镜：`apps/mini/src/services/creation.ts:4-36`、`apps/mini/src/pages/creation/edit.tsx:103-135`。
- 合成页已实现基础、AI、精品三档选择：`apps/mini/src/pages/render/compose.tsx:34-38,212-240`。

### 1.2 当前可确认的主流程

1. 微信一键登录；服务端创建/恢复商家会话。开发模式可出现本地联调登录。
2. 选择或新建门店，门店下维护菜品；可维护老板人设与活动。
3. 新建创作，选择门店，菜品可选，输入标题可选。
4. 生成口播文案，再生成分镜脚本；代码中生成按钮目前没有展示动态预估积分、会员/订阅门槛或“重新生成”明确动作。
5. 按分镜上传视频，客户端上报时长/大小并绑定到分镜；镜头库可提供拍摄技巧及示范视频（没有示范视频时仅不显示按钮）。
6. 合成页预览已上传素材，选择基础/AI/精品档，调整基础/AI 档统一调色，查看前端估算积分并提交。
7. 基础/AI 任务按轮询查询，精品任务进入人工队列；失败按代码/文档约定退款。
8. 订阅与加油包在充值页购买；“加油包仅订阅用户可购买”。

主要证据：`docs/04-页面流程与验收.md:29-53`、`docs/05-计费规则.md:9-20,76-113,168-187`、`apps/mini/src/pages/creation/edit.tsx:70-187`、`apps/mini/src/pages/creation/shots.tsx:42-137`、`apps/mini/src/pages/render/compose.tsx:123-165,270-312`、`apps/mini/src/pages/recharge/index.tsx:53-165`。

### 1.3 最大产品风险

- 需求/计费口径没有收敛：页面验收文档仍写 v4 固定豆价且“取消会员功能卡点”，现行 v5 却是订阅硬卡点、积分动态成本计费。两份文档都标为设计依据，极易造成前后端、运营和客服口径不一致。
- 首次使用存在“先建资产、后发现不能生成”的风险：创建页允许无菜品创建；生成页没有直接展示当前订阅状态、预估积分和余额；现行 v5 又要求订阅后才可调用。
- 成片结果不可稳定回收：合成页只在本次轮询成功后拉取播放地址，历史成功任务和人工交付任务重进页面不会自动恢复成片播放；页面没有保存/下载按钮，和验收文档承诺不一致。
- 首页的“爆款/优秀作品/播放量/同行监控”等内容有静态 mock 或待开发入口，容易形成能力预期落差。
- 关键账务展示口径有漂移：状态层 `balance` 在不同接口中分别被赋为充值余额或 available，首页又将 `balance + grantBalance`，合成页只看 `balance`。

## 2. 用户体验与信息架构问题

### P0-1：文档版本冲突直接影响购买与生成链路

**证据**

- `docs/04-页面流程与验收.md:4-6` 写明全链路按豆计费、无会员功能卡点；`docs/04-页面流程与验收.md:81-91` 仍是文案 5 豆、分镜 10 豆、合成 30 豆。
- `docs/05-计费规则.md:1-20` 明确 v5 优先，要求订阅是文案/分镜/合成硬前提，且改为成本×系数和按时长计费。
- `docs/06-全链路梳理与三档生成方案.md:59-63` 的历史验证记录写文案扣 5、分镜扣 8，但这些数字可能只是动态计费样本，不能单独判定与 v5 冲突，更不能当作现行固定价承诺。
- 前端合成页按档位系数估算：`apps/mini/src/pages/render/compose.tsx:23-56`；生成文案/分镜按钮不展示价格或区间：`apps/mini/src/pages/creation/edit.tsx:148-168`。

**影响**

用户在不同页面可能看到不同价格/权益，客服无法解释“为什么被扣的不是页面写的数”；研发也可能把已作废的固定价继续实现。动态计费缺少生成前的可理解预估，会降低付费确认率并放大投诉。

**建议**

P0：确定唯一生效规则，删除/归档旧版或在文档顶部加醒目标记；将产品文案统一为“订阅开通功能 + 积分按实际成本/时长消耗”。所有付费动作展示“预估区间/计算依据、当前订阅状态、可用积分、失败退款规则”，结果页和积分流水展示实际扣减。验收标准：抽样 20 个生成/合成场景，页面预估与后端最终扣费差异仅允许由真实成本/实际耗时造成，并在结果页可解释。

### P0-2：历史成片和下载闭环不完整

**证据**

- 合成页初始只加载创作详情和任务列表：`apps/mini/src/pages/render/compose.tsx:86-91`。
- `getResultPlayUrl` 只在本次提交后的轮询成功分支调用：`apps/mini/src/pages/render/compose.tsx:147-156`。
- 当前页面没有保存到相册、下载或复制链接按钮；但验收文档明确要求保存/下载且可反复下载：`docs/04-页面流程与验收.md:49-53,124-126`。
- 精品任务提交后不轮询，代码提示“交付后重新进页可见”，但加载逻辑并未把历史 SUCCESS 转成可播放 URL：`apps/mini/src/pages/render/compose.tsx:139-143,86-91`。

**影响**

用户离开页面后无法可靠找回成片；精品档交付后尤其容易出现“后台已完成、用户端看不到”的断点。产品核心价值“出片”无法沉淀为可分享、可发布的结果。

**建议**

P0：列表加载后自动选最近一条 SUCCESS 并换取播放 URL；对人工交付完成用同一逻辑恢复。增加“保存到相册/下载”动作、失败重试和结果历史列表，标记档位、完成时间、实际扣积分。验收标准：成功任务离开页面再进入，30 秒内可播放；真机验证保存相册失败时有下载链接降级；同一成片重复下载不扣积分。

### P0-3：订阅门槛没有在创作前置位置被解释，且后端错误映射疑似破坏统一引导

**证据**

- v5 要求未订阅不能使用文案/分镜/合成：`docs/05-计费规则.md:9-20,168-187`。
- 登录成功后直接进入首页：`apps/mini/src/pages/login/index.tsx:57-61`；首页仅在有会员时显示“已订阅”，无会员时没有同等显著的订阅说明：`apps/mini/src/pages/home/index.tsx:74-96`。
- 创建创作只校验门店，不校验订阅或积分：`apps/mini/src/pages/creation/edit.tsx:51-68`。
- 生成按钮只有“生成文案/生成分镜”文字，没有成本区间、订阅状态或余额：`apps/mini/src/pages/creation/edit.tsx:148-168`。
- 服务层确实调用 `requireSubscription`：`server/src/services/creation.service.ts` 中 `generateCopy`/`generateShots`；但路由 `handleAiErr` 仅处理 `BeanNotEnoughError`、`CreationNotFoundError`、`ScenePendingError`，没有 `SubscriptionRequiredError` 分支：`server/src/routes/creations.ts:10-12,111-119`。静态证据表明未订阅异常可能落到通用 500，而非规则要求的 2005；需用未订阅账号联调确认。

**影响**

用户投入时间填写门店/菜品/标题、甚至上传素材后，才发现功能不可用或需要购买 ¥980 订阅；这会显著降低激活率和付费信任。若后端确实返回 500，前端无法渲染“立即订阅/订阅后自动继续”，用户会把业务拦截误认为系统故障。

**建议**

P0：首次进入或点击首个付费能力时明确展示订阅价值、周期、赠送积分、空间配额和取消/到期规则；创建页允许体验但在生成前展示门槛与预估，未订阅可一键订阅并自动回到原操作。补齐 `SubscriptionRequiredError → 2005 SUBSCRIPTION_REQUIRED` 映射并做 API/真机验证。记录 `login → 建店 → 生成页 → 订阅页 → 首次成功生成` 漏斗。

### P1-1：创作流程缺少赛道/复杂度选择，和设计流程不一致

**证据**

- 页面设计要求“选菜品 → 选赛道 → 选复杂度”：`docs/04-页面流程与验收.md:17,37-43`。
- `createCreation` 入参只有 storeId、dishId、title：`apps/mini/src/services/creation.ts:52-53`；创建页也只有门店、菜品、标题：`apps/mini/src/pages/creation/edit.tsx:103-135`。
- 数据类型虽有 `track`、`complexity`：`apps/mini/src/services/creation.ts:4-14`，但用户无法在创建页选择。

**影响**

用户无法主动表达“流量款/介绍款/质量款”和镜头复杂度，AI 生成结果与期望不匹配，且复杂度带来的时间/成本差异没有在转化前呈现。

**建议**

P1：补充两组可解释的选择控件，给出示例和预计镜头数/时长/积分区间；默认值需说明。指标：赛道/复杂度选择率、生成后重生成率、生成失败/不满意反馈率。

### P1-2：分镜可继续合成但没有完成度拦截和缺口解释

**证据**

- 上传页总是展示“下一步：合成成片”，没有按未上传数量禁用或解释：`apps/mini/src/pages/creation/shots.tsx:132-137`。
- 合成页对未上传素材只标记“缺素材”，但提交按钮未在前端按缺口阻断：`apps/mini/src/pages/render/compose.tsx:192-209,270-292`。
- 后端错误文案仅为“请先为分镜上传素材”：`apps/mini/src/services/request.ts:23-27`。

**影响**

用户可能在缺素材时走到合成提交才失败；错误出现在流程末端，返工成本高。

**建议**

P1：显示“已上传/总数”、缺口分镜列表和“去上传”入口；默认至少要求一个素材，若允许部分分镜合成必须明确计费和成片语义。指标：合成前 4003 错误率、上传页到成功合成转化率。

### P1-3：门店上下文可见性不足，首页显示内部 ID

**证据**

- 首页门店显示为 `门店 #${currentStoreId}`：`apps/mini/src/pages/home/index.tsx:82-86`，而非门店名称。
- 门店切换在独立页面完成，创建页又重新选择门店：`apps/mini/src/pages/store/list.tsx:31-42`、`apps/mini/src/pages/creation/edit.tsx:103-120`。
- 请求层通过 `X-Store-Id` 自动附带当前门店：`apps/mini/src/services/request.ts:68-80`。

**影响**

多门店商家难以确认当前操作归属，尤其首页、积分/素材和创作列表可能产生错门店感知；内部 ID 对用户没有价值。

**建议**

P1：全局展示门店名称和切换入口；创作列表提供门店筛选/门店标签；切换门店后明确刷新哪些数据。指标：门店误操作反馈、切换后返回率、创作归属纠错次数。

## 3. 转化、留存、运营和商业化

### P0-4：价格信息和积分账务口径不稳定

**证据**

- `MerchantState` 将 `balance` 定义为余额，另有 `grantBalance`：`apps/mini/src/store/merchant.ts:17-21,23-35`。
- `refreshBean` 将 `balance` 赋为 `r.balance`：`apps/mini/src/store/merchant.ts:89-96`；`refreshMe` 却将 `balance` 赋为 `me.balance.available`：`apps/mini/src/store/merchant.ts:99-115`。
- 首页显示 `Number(balance) + Number(grantBalance)`：`apps/mini/src/pages/home/index.tsx:90-95`；合成页余额校验只比较 `balance`：`apps/mini/src/pages/render/compose.tsx:123-133`。
- v5 规定赠送积分到期清零、自购积分永久有效：`docs/05-计费规则.md:35-41`，但小程序主要只显示“可用积分/赠积分”，没有到期时间和消费优先级解释：`apps/mini/src/pages/mine/index.tsx:74-86`、`apps/mini/src/pages/recharge/index.tsx:93-99`。

**影响**

首页数字可能和合成拦截数字不一致，用户会认为系统少算或多扣；赠送积分到期会产生高投诉风险。运营也难以回答余额、冻结、赠送积分的区别。

**建议**

P0：定义唯一前端余额模型：可用总积分、赠送积分、购买积分、冻结积分分别来自同一 `/me` 快照；所有页面统一使用 `available`。流水展示来源、用途、冻结/退回、到期时间和消费优先级。指标：余额相关客服投诉、支付后余额刷新失败率、积分申诉率。

### P1-4：订阅页的价值表达不足且加油包标签容易误导

**证据**

- v5 订阅实质是 ¥980/30 天并赠 98,000 积分、5GB 空间：`docs/05-计费规则.md:24-41`。
- 充值页只按后台套餐名、有效期和“赠积分”展示：`apps/mini/src/pages/recharge/index.tsx:110-129`；页脚只写“1元 = 100积分 · 加油包仅订阅可用”：`apps/mini/src/pages/recharge/index.tsx:165`。
- 加油包页面非会员只显示锁定提示，仍渲染不可购买卡片：`apps/mini/src/pages/recharge/index.tsx:134-161`。

**影响**

用户无法估算一次短视频大致可用多少次；高价订阅缺少“适合谁/包含什么/到期如何处理”的解释。不可购买卡片会制造“页面故障”感。

**建议**

P1：在订阅卡片展示典型使用量示例、空间额度、积分有效期和失败退款；非会员的加油包仅展示“订阅后可解锁”摘要，并提供明确跳转，不渲染灰色购买按钮。指标：订阅详情页停留、开通转化、加油包购买转化、退款/咨询率。

### P1-5：运营后台有财务与技术指标，但缺少产品漏斗和用户行为指标

**证据**

- 仪表盘当前指标集中在商家、门店、创作、合成、充值、AI 成本和毛利：`apps/admin/src/pages/Dashboard.tsx:6-20,47-90`。
- 后台菜单有积分流水、合成任务、AI 日志、镜头库和系统设置，但没有漏斗、留存、素材上传失败、生成满意度或复购视图：`apps/admin/src/layouts/AppLayout.tsx:18-32`。

**影响**

只能知道“做了多少任务/花了多少钱”，不知道用户在哪一步流失、为什么重试或为何不复购，运营无法验证产品改动。

**建议**

P1：新增按日/周 cohort 的激活、首个成功文案、首个成功成片、订阅、复购、7/30 日留存漏斗；按门店/赛道/档位分析。指标必须与埋点字典绑定，避免仅看接口调用量。

### P1-6：精品人工交付存在运营容量和通知缺口

**证据**

- 精品任务进入人工队列，承诺 48 小时内交付：`docs/06-全链路梳理与三档生成方案.md:142-170`。
- 后台交付依赖人工填写 COS Key：`apps/admin/src/pages/RenderTasks.tsx:107-132,202-217`；文档也承认尚未实现后台直接上传：`docs/06-全链路梳理与三档生成方案.md:290-294`。
- 小程序精品提交后不轮询，只提示重新进页可见，订阅消息待接入：`apps/mini/src/pages/render/compose.tsx:139-143`、`docs/06-全链路梳理与三档生成方案.md:262-267,290-294`。

**影响**

人工生产规模受后台操作和 COS 复制粘贴限制；用户不知道交付进度，48 小时承诺容易超时后才被动退款。

**建议**

P1：增加人工队列容量、接单人、SLA 预警和交付失败原因；后台支持直传；小程序显示预计交付时间并接入订阅消息。指标：接单等待时长、按时交付率、人工失败率、精品退款率。

### P0-5：AI 合成的配音/字幕能力未达到真实付费发布门禁

**证据**

- `server/src/render/tts.ts:1-3,18-23,34-53` 明确标注真实语音合成尚未实现；即使配置供应商也会抛错并回退静音轨。
- 架构师确认 `server/src/services/render.service.ts:230-242` 未把 `Shot.line` 写入 clips，而 `server/src/render/worker.ts:163-179` 读取该字段；`server/src/render/synthesis.ts` 在 `line` 为空时不会生成 SRT。因此静态证据只能支持“可能得到无配音且无字幕的成片”，最终音视频表现仍待真实媒体验证。
- 计费文档将 AI 合成定义为“AI 配音(TTS) + 字幕烧录 + 智能节奏”，且前端默认 AI 档：`docs/05-计费规则.md:125-140`、`apps/mini/src/pages/render/compose.tsx:34-38,71-72`。
- 合成页向用户展示“配音 + 字幕 + 节奏”和“AI 生成（推荐）”，没有说明当前能力未验收：`apps/mini/src/pages/render/compose.tsx:34-38,212-240`。

**影响**

用户为“AI 配音/字幕”预期付费，可能得到无配音且无字幕的成片，属于核心价值未兑现，容易引发退款和负面口碑。后台配置 TTS 供应商不等于实际能力已可用。

**建议**

P0（真实付费发布门禁）：在真实 TTS、字幕数据传递、字幕烧录和最终音轨均通过媒体验收前，关闭未验收的 AI 收费入口或将其明确置为不可购买的内部演示；任何演示标签必须符合实际输出，不能暗示已有配音/字幕。完成腾讯云/火山任一供应商的真实合成、超时、降级、字幕和结果音轨验收后再开放收费。后续 TTS/字幕能力开发可按首发范围重新调整优先级。指标：AI 档音频存在率、字幕存在率、TTS 成功率、静音/无字幕成片投诉与退款率。

### P2-1：首页内容当前不能承担真实留存

**证据**

- 首页明确注释“模拟优秀作品展示数据（无 API 依赖）”：`apps/mini/src/pages/home/index.tsx:8-16`。
- 分类也是静态数组：`apps/mini/src/pages/home/index.tsx:18-18,188-193`。
- “同行账号监控”点击只显示“即将上线”：`apps/mini/src/pages/home/index.tsx:156-167`。
- 全链路报告将首页优秀作品/分类标为 mock：`docs/06-全链路梳理与三档生成方案.md:101-113`。

**影响**

用户会把示例播放量和“实时爆款/数字人 3.0”等当成真实产品能力，实际点击后无法使用，损害信任；静态内容也无法驱动回访。

**建议**

P2：上线前移除未实现能力或清晰标注“即将上线”；接入真实精选成片/镜头库并按餐饮品类、城市、活动场景推荐。精选内容必须有可播放预览和“用此模板创作”入口。

## 4. 视觉语言与小程序可用性

### 4.1 已确认的视觉优点

- 小程序主题有明确的品牌红、琥珀权益色、中性灰和浅灰背景，整体视觉规则集中：`apps/mini/src/styles/theme.scss:1-55`。
- 合成页采用底部固定提交栏并考虑安全区：`apps/mini/src/pages/render/compose.scss:195-236`。
- 主要按钮、状态标签和图标有统一的 TDesign/主题变量基础：`apps/mini/src/app.config.ts:19-27`、`apps/mini/src/styles/theme.scss:5-50`。

### 4.2 可用性问题

1. **关键操作价格不可见**：验收要求所有扣豆按钮显示价格：`docs/04-页面流程与验收.md:25`；但生成文案/分镜按钮无价格，且 v5 要求区间预估：`apps/mini/src/pages/creation/edit.tsx:148-168`、`docs/05-计费规则.md:88-100`。
2. **生成前缺少状态反馈**：创建页加载/接口失败多为静默 catch，列表加载只有“加载中”；例如 `apps/mini/src/pages/creation/edit.tsx:31-41,96-100`。网络慢或 AI 排队时用户难以判断是否提交成功。
3. **触控和信息密度需真机验收**：合成页三档卡片横排，宽度由 `flex: 1` 平分：`apps/mini/src/pages/render/compose.scss:79-95`；在窄屏、字体放大或较长套餐名下可能出现折行拥挤，必须在 320/375/414 宽度真机检查。
4. **视觉语义仍有“豆/积分”混用**：代码 class 仍大量使用 `bean`（`home__info-bean`、`mine__bean`、`ds-bean`），但用户文案改成积分。对用户虽不直接可见，但增加维护和运营沟通成本：`apps/mini/src/pages/home/index.tsx:74-96`、`apps/mini/src/styles/theme.scss:39-45`。
5. **后台与小程序视觉体系割裂**：后台是深蓝侧栏和蓝色登录渐变：`apps/admin/src/styles.css:4-9,23-26`；小程序为红白/琥珀。后台面向运营可独立，但品牌状态色、术语（会员/订阅、豆/积分）应统一。
6. **协议入口不满足可用性/合规可发现性**：登录页只显示“授权即表示同意《用户协议》和《隐私政策》”纯文本：`apps/mini/src/pages/login/index.tsx:97-107`，没有可点击的协议页面或勾选状态；而上线检查要求小程序有可见入口：`docs/04-页面流程与验收.md:140-151`。
7. **示范视频缺省状态不够明确**：镜头库只有存在 `demoVideoKey` 才显示“看示范”：`apps/mini/src/pages/creation/shots.tsx:104-119`；设计文档要求无配置时显示占位：`docs/04-页面流程与验收.md:45-47`。用户无法区分“没有示范”还是加载失败。

## 5. 产品指标建议

### P0 上线门槛

| 指标 | 目标/验收方式 |
|---|---|
| 首次成功成片率 | 新注册用户 24 小时内完成至少 1 个 SUCCESS；按登录、建店、生成文案、分镜、上传、提交、成功分步统计 |
| 成片可回收率 | 成功任务离开再进入页面，播放/下载恢复率 >= 99% |
| 账务一致性 | 首页、充值页、合成页、流水页余额来自同一快照；并发扣费不负数、失败全额退款 |
| 价格理解率 | 用户在提交前能回答“本次预计扣多少、失败如何处理”；可用 5 人可用性测试验证 |
| 订阅门槛清晰度 | 未订阅用户在首次点击付费功能前看到订阅价格、周期、权益和一键继续路径；订阅后原操作自动恢复 |
| 协议可达性 | 登录前可打开用户协议和隐私政策，真机可返回登录且状态可见 |

### P1 增长与运营

| 指标 | 目标/验收方式 |
|---|---|
| 激活转化 | 登录到首次成功文案、首次成功成片分别建漏斗，按门店是否完整分层 |
| 付费转化 | 订阅页曝光→详情→支付→成功；加油包仅统计订阅用户 |
| 成片复用 | 成片下载/保存/分享率，7 日内二次创作率 |
| 质量反馈 | 重新生成率、失败率、人工退款率、示范视频点击完成率 |
| 留存 | 1/7/30 日回访、再次上传素材、再次生成和复购率 |
| 精品履约 | 接单等待、按 SLA 交付、通知到达、退款率 |

### P2 内容与生态

| 指标 | 目标/验收方式 |
|---|---|
| 精选内容有效性 | 精选作品播放完成率、模板复用率、按品类/城市的点击转化 |
| 镜头库覆盖 | 六类镜头库配置率、示范视频可用率、各分镜上传成功率 |
| AI 成本毛利 | 各模型/场景成本、fallback 率、每条成片毛利和退款成本 |

## 6. 优先级路线图

### P0：上线前必须完成

1. 统一 v5 计费、订阅、积分术语和所有前端/后台/验收文档；删除固定豆价旧口径。
2. 修复历史成片恢复、保存/下载、失败重试和精品交付后的用户可见闭环。
3. 统一余额快照和积分流水口径，补赠积分到期提示、冻结/退款展示。
4. 在生成/合成前展示订阅状态、预估积分区间、余额和退款规则；支付/订阅成功后自动继续原操作。
5. 补协议可点击入口与勾选/可达性，完成真机支付、COS、FFmpeg、TTS 验证。
6. 合成前明确素材缺口，避免到提交末端才返回 4003。

### P1：提升转化与可运营性

1. 补赛道、复杂度选择和生成偏好；让用户理解镜头数、时长和成本关系。
2. 全局展示门店名称、切换器和创作归属，避免内部 ID。
3. 增加产品漏斗、留存、质量、退款和人工履约仪表盘。
4. 完善精品人工工作台直传、SLA 预警和订阅消息。
5. 统一“积分/订阅/加油包”在后台和小程序的术语、状态色和帮助文案。

### P2：建立真实内容与复访机制

1. 将首页 mock 精选改为真实精选成片/镜头库，提供播放与模板复用。
2. 移除或标注同行监控、数字人等未实现入口。
3. 增加脚本润色、BGM、节奏、标题和内容安全等 AI Skill，但每项能力需单独计费说明和失败降级策略。
4. 建立用户反馈、作品质量评分和按餐饮场景的模板运营机制。
