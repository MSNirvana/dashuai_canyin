# 08 · 上传视频素材后展示缩略图

## 需求

拍摄页（`pages/creation/shots`）绑定视频素材后，只能看到一行「✓ 已上传」文字，用户无法确认自己传的到底是哪条素材。需求：**上传视频后要能看到视频缩略图**。

## 现状与根因

| 环节 | 现状 |
| --- | --- |
| `media_asset.cover_key` | 表里有该字段，但**上传流程从不写入**，恒为 `NULL` |
| `/upload/local` | 落盘即完，不做任何抽帧 |
| `/upload/complete` | 只登记 `cosKey`，无封面参数 |
| `GET /creations/:id` | 只返回 `assetId` / `assetDurationMs`，无任何可展示的图 |
| `pages/creation/shots` | 只有「✓ 已上传」文本 |

结论：**封面字段是预留的，但从未被填充**。因此不能只改前端——必须先把 `coverKey` 落上。

## 方案

双通道生成封面，最终统一写回 `media_asset.cover_key`：

### 通道 A · 本地存储模式（当前开发环境，服务端抽帧）

本地模式下视频文件就落在服务器磁盘（`server/storage/uploads/{merchantId}/...`），服务端能直接读，**用 ffmpeg 抽第 1 帧**：

- 新增 `server/src/lib/thumbnail.ts`
  - `generateVideoCover(videoPath, outPath, { atSeconds, width })`：`spawn('ffmpeg')` 抽帧，先试 `-ss 1`（避开开场黑帧），失败退回 `-ss 0`；默认缩放到宽 640（高取偶数，jpg 要求）；**15s 超时 + 全程 best-effort，失败绝不阻断上传**。
  - `coverKeyForVideoKey(videoKey)`：`uploads/{m}/a.mp4` → `uploads/{m}/covers/a.jpg`（与视频同前缀，天然满足商家前缀校验）。
- `/upload/local` 落盘后若 `type === 'VIDEO'` 就抽帧，成功则把 `coverKey` 一并写入素材。

### 通道 B · COS 模式（服务端读不到文件，客户端上报）

COS 直传时文件不经过服务器，服务端抽不了帧。改用微信自带的抽帧结果：

- `Taro.chooseMedia` 选视频时会返回 `thumbTempFilePath`（封面图临时路径）。
- 小程序先把这张封面图按 `IMAGE` 传一次，拿到其 `cosKey`，再作为 `coverKey` 随视频一起提交 `/upload/complete`。
- `confirmUpload` 新增 `coverKey` 入参，并**校验封面键同样落在当前商家前缀下**（防借用他人对象键）。

### 兜底 · 历史素材补生成

改动前上传的素材 `coverKey` 全是 `NULL`（本地库有 27 条），重新上传不现实。新增接口：

- `POST /creations/:id/ensure-covers`
  - 只挑「已绑定到该创作、`coverKey` 为空、`type = VIDEO`」的素材；
  - 本地模式逐个抽帧并回写 `coverKey`，返回 `{ generated, pending }`；
  - **幂等**：已有封面 / 文件不存在 / 抽帧失败都只计入 `pending`，不报错、不重复生成。
- 拍摄页进入时若发现「有素材但无 `coverUrl`」，自动触发一次，成功后刷新详情。

## 接口变更

| 接口 | 变更 |
| --- | --- |
| `POST /upload/local` | 新增：视频落盘后服务端抽帧写 `coverKey`；可选接收客户端 `coverKey` |
| `POST /upload/complete` | 新增可选入参 `coverKey`（客户端抽帧结果） |
| `GET /creations/:id` | 每个分镜新增 `coverUrl`（由 `coverKey` 签发的临时 URL，无封面为 `null`） |
| `POST /creations/:id/ensure-covers` | **新增**：补生成封面，返回 `{ generated, pending }` |

## 小程序交互（`pages/creation/shots`）

- 卡片底部改为缩略图区：
  - 有图 → `<Image mode="aspectFill">` 铺满 + 居中播放按钮 + 右下角时长胶囊 + 左上角「✓ 已上传」；
  - 无图（抽帧中/失败）→ 占位块「🎬 缩略图生成中」，**不显示破图**。
- **选中即见**：`chooseMedia` 返回的 `thumbTempFilePath` 先放进本地 state 立刻渲染，不必等上传完成。
- **点击缩略图播放原视频**：新增 `GET /media/:assetId/play-url` 调用（`getAssetPlayUrl`），用 `Taro.previewMedia` 播放。
- 已上传的分镜补了「重新拍摄」按钮（此前一旦绑定就无法更换）。
- 顶部在补生成期间显示「正在生成缩略图…」。

## 注意

- **ffmpeg 必须可用**（`FFMPEG_PATH` 可覆盖路径）。缺失时上传仍成功，只是 `coverKey` 为空、前端显示占位图，后续调 `ensure-covers` 可重试。
- 封面文件与视频同前缀 `uploads/{merchantId}/covers/`，因此复用了 `media.service.getPlayUrlByKey` 的商家前缀校验，**没有新增越权面**。
- `coverUrl` 是 1 小时有效的临时签名 URL，不要缓存到本地存储。
