# 这个目录里的图**不进代码包**

`home/` 下的 7 张图（6 张 `.jpg` + `slogan-banner.png`）都是**上传源**，
页面里引用的是 CDN 直链，不是这些文件。

- 页面代码引用的是 `src/constants/static-assets.ts` 里的常量（由 `npm run assets:upload` 生成）。
- 改了这里的图，**必须**跑 `npm run assets:upload` 重新上传，否则线上还是旧图。
- 想确认某一轮构建有没有把这些图打进包：看构建后 `dist/weapp/assets/` 下是否还有 `home/` 目录 —— 正常应该**没有**。

留在包里的是：

- `../logo.png` —— 展示最大 64rpx(32pt)，96px 已是 3x 屏上限，14KB；
- `../tabbar/*.png` —— `app.json` 的 `tabBar.iconPath` **只接受本地路径**，无法上 CDN。

两者合计约 32KB，远低于微信「图片和音频资源超过 200K」的建议线，而换来的是品牌标与 tabBar 零延迟渲染。

`slogan-banner.png` 也在这个目录里，但**同样走 CDN**（2026-09-16 从「本地内联的 1.2KB SVG」换过来的）：

- 原来那张是代码画的 750×260 SVG（1.2KB），webpack 内联成 base64 比多一次网络请求更划算；
- 现在换成了一版**成品海报**（深色字 + 橙色描边 + 胶片带 + 半透明菜品照，1125×411）。
  它是照相级内容且**带透明底**，base64 内联会让包体涨 100KB 以上；
- 处理方式：把原图纯白底**扣成透明**（从四边 flood fill，只吃与边界连通的白，
  不会啃掉图里同样是白色的胶片带与盘沿），再做反预乘去掉白边，
  最后量化成**调色板 PNG（256 色 + tRNS，半透明保留 111 档）**，73KB。
- 转出来的宽高比 2.737，卡片内宽 678rpx ⇒ 展示高 248rpx。

### ⚠ 垂直构图：裁切基准是「墨量重心」，不是「alpha 包围盒」

第一版出图时用了最直觉的做法——**把四周全透明的边裁掉**（`alpha > 8` 的 bbox）。
结果文字被顶到画布上沿、下方空一大片。根因：

- 源图 1748×900，真正的字只占 y≈219–640；
- 但左下/右下还有**很淡的半透明装饰**（视频播放器卡片、菜品残影），一直拖到 y≈846；
- 于是 bbox = [195, 846]：**上边只留了 24px 余量、下边却空了 200px**。

正确的判据是**墨量**（`alpha × (255-lum)^1.5`）的行重心——源图墨量重心 y=427，
而画布中线 450，即**原设计本身基本是居中的**，是裁切把它弄歪了。
现在改成以重心为轴上下各留 ~110px（`y ∈ [110, 748]`），输出后墨量 2%/98% 落在
y=84 / y=335（画布高 411）⇒ 上下留白 84 : 75，视觉居中。

下边界定在 748 是刻意选的：右下角那台视频播放器卡片底边在 y≈710，748 能整台留住，
不会把它切成半截。

- ⚠ 换图后要同步改 `pages/home/index.scss` 里 `&__slogan-image` 的 `height`（写了注释说明算法）。

留在**包里**的仍然只有 `../logo.png` 与 `../tabbar/*.png`。
