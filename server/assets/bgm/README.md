# 配乐曲库（BGM）

这个目录是**运行时数据**，不是源码。渲染时按「风格 → 曲子文件」在这里找曲子。

## 契约：两个位置并存，取用时**池子优先、单文件兜底**

| 位置 | 形态 | 说明 |
| --- | --- | --- |
| **池子** | `LIGHT/` 目录，内含任意多首 | 同风格多条 ⇒ 渲染时**随机抽一首**（每条片子配乐不重样） |
| **单文件** | `LIGHT.<ext>` | 老约定，线上现存曲库就是这种，**继续有效** |

- 取用顺序：**池子里有任何一首可用就随机抽它**；池子为空才回退单文件；
  两头都没有 ⇒ 返回 `null`，调用方回退合成垫底。
- 所以「换生成源」（ChatCut ↔ 火山）**不会覆盖也不会删掉**已有曲子 —— 两个位置互不干涉。
- 扩展名白名单：`mp3 / m4a / aac / wav / flac / ogg / opus`（单文件多扩展名时按此顺序取第一个）。
- 每首曲子旁边的 `.json` 是**旁注元数据**（来源 / 提示词 / 时长 / 授权说明），渲染不读它，
  但 `.json` **不能**被当成曲子取到 —— 两个查找函数都只认音频白名单。
- 目录可由环境变量 `BGM_LIBRARY_DIR` 覆盖；没配就按「模块相对 `../../assets/bgm`」解析，
  所以 `src/` 与 `dist/` 下都能跑。

> ★★ 实现里有个**必须分开**的点：`resolveBgmTrack()` 是「池子优先」，
> 而 `singleFileBgmTrack()` **只看单文件**。补货脚本清理「同风格单文件残留」时必须用后者 ——
> 用前者会在池子非空时删掉**刚攒进池子的曲子**（补一首删一首，池子永远长不大）。
> 守护（`bgm:verify`）为此专门钉了一条断言。

## 两条硬约束

1. **曲子必须不比成片短**（≥ 65s，代码里是 `BGM_MIN_DURATION_MS`）。
   `synthesis.ts::mixAudioTracks()` 用 `amix=duration=longest` 且只输出一条音频流，**不做循环**；
   比成片短的曲子会在中途静音，而且**不报错**。
   ⚠ 不要为了补齐而加 `-stream_loop -1`：混音输出会变成**单条无限流**，`-shortest` 没有有界流可比，
   渲染会**永久挂住**。要循环必须同时给 `-t <成片时长>`，那是另一笔改动。
2. **别手工删这里的东西**。删掉某个风格只是退回合成垫底（不会让出片失败），
   但那正是「配乐像嗡声不像曲子」这个老问题的成因。

## 补货：把池子维持到目标数量

```bash
cd server
npm run bgm:replenish                        # 看现状与计划（不发任何请求）
npm run bgm:replenish -- --yes               # 按缺口补、并把超额部分淘汰（幂等）
npm run bgm:replenish -- --target=8 --max=3  # 目标 8 首/风格，单次每风格最多补 3 首
npm run bgm:replenish -- --prune-only --yes  # 只淘汰超额，不生成
npm run bgm:replenish -- --list              # 只看现状
```

策略三条（每次跑一遍都是幂等的）：池内 **> 目标** ⇒ 淘汰最旧的（连 `.json` 一起清）；
**< 目标** ⇒ 补到目标（单次每风格最多 `--max` 首）；**= 目标** ⇒ 不动。

### 池子能有多大 —— 受提示词表条数限制

`volcano` 源的曲子描述来自 `volcano-bgm.ts::VOLCANO_BGM_PROMPTS`（每个风格一张表）。
补货**只会挑池里没用过的描述**（读侧车 `.json` 的 `prompt` 字段回溯），因此：

- **目标数不要超过表里条数**。超了就只能重复已有描述，池子里会长出**近乎重复**的曲子。
  守护 `bgm:verify` 把这个关系钉在 `BGM_POOL_TARGET` 上 —— **把目标调大而提示词不够，守护立刻红**。
- 想要更大的池子，**先往表里加词**，再调 `--target`。加词只要满足三条：纯中文（该接口 `Text`
  不支持英文）、写明曲风/乐器/情绪/场景、并显式排除人声（配乐要垫在口播下面）。三条都由守护断言。
- ⚠ 顺序取词有个前提：**池内已有曲子占据了 0..n-1 号描述**。手工单发（`bgm:generate`）是**随机**
  取词的，一旦池子被随机播种过，纯按序号取词就会撞上已经用过的那条描述 ⇒ 所以补货改成了
  「先用没用过的」；`usedBgmPromptTexts` 就是为此存在的。

## 单风格生成 / 取回

```bash
npm run bgm:generate -- --list                              # 先看现状
npm run bgm:generate -- --style=ALL --yes                   # 补齐缺口（已存在的会跳过）
npm run bgm:generate -- --style=LIGHT --yes --force         # 强制重造某一首
npm run bgm:generate -- --source=volcano --style=LIGHT --yes # 改用火山生成（落池子）
npm run bgm:generate -- --style=UPBEAT --asset=<assetId> --yes --project=<projectId>
                                                            # 只把**已生成好**的素材取回落盘（不再花生成额度）
npm run bgm:verify                                          # 守卫：风格清单同源 / 池子取用 / 火山契约
```

**生成要花钱**（ChatCut 消耗额度；火山按秒计费，约 0.002 元/秒），
所以两个脚本都**默认 dry-run**，必须显式加 `--yes`。

### 两个生成源

| `--source` | 走什么 | 凭证 | 落盘 |
| --- | --- | --- | --- |
| `chatcut`（`bgm:generate` 默认） | ChatCut `submit_music`（mureka-9） | MCP 桥（OAuth） | 默认单文件；加 `--pool` 写池子 |
| `volcano`（`bgm:replenish` 默认） | 火山 `GenBGMForTime`（豆包音乐 v5.0） | `VOLCENGINE_ACCESS_KEY` / `VOLCENGINE_SECRET_KEY`（**AK/SK v4 签名**） | **只写池子** |

> ⚠ 火山的 AK/SK 与火山 **TTS** 的 `X-Api-Key` **不是同一套凭证**，别混。
> 缺凭证时脚本会明确报「缺哪两个变量」且**不会**静默退回另一个源 —— 换源必须是显式的。
> 这两条链路都只在**补货**时联网；渲染管线永远只读本地文件，第三方挂了不影响出片。

### 火山这条源的两个已知约束

- `Text` **仅支持中文**（守护里钉了「纯中文」断言）。
- 公共池 **QPS ≤ 2** 且要排队、单首生成 **1–5 分钟** ⇒ 这正是「不把生成放进出片链路、
  改成后台补货」的原因。补货脚本**顺序**生成，不要并发轰它。
